# 데이터 정제 기준

## 1. 문서 목적

본 문서는 상황 기반 생활 장소 추천 지도 서비스에서 외부 데이터를 수집한 뒤, DB에 저장하기 전에 적용할 데이터 정제 기준을 정의한다.

현재 수집한 데이터는 CSV, JSON, API 확인 자료 등으로 구성되어 있으며, 실제 DB 저장은 Django 모델과 import command가 작성된 이후 진행한다.

따라서 본 문서는 원본 데이터를 직접 수정하기 위한 문서가 아니라, 향후 import 과정에서 적용할 정제 기준을 정리하는 문서이다.

---

## 2. 원본 데이터 보관 원칙

원본 데이터는 수정하지 않고 별도로 보관한다.

```txt
ExData/
├─ CSVData/
│  ├─ citypark/
│  ├─ freewifi/
│  ├─ smokearea/
│  └─ toilet/
└─ JsonData/
```

원본 데이터를 직접 수정하지 않는 이유는 다음과 같다.

- 원본 출처를 추적하기 위해
- 인코딩 문제를 방지하기 위해
- 좌표 소수점 손실을 방지하기 위해
- 모델 변경 시 다시 정제할 수 있도록 하기 위해
- 데이터 오류 발생 시 원본과 비교하기 위해

---

## 3. 공통 정제 기준

모든 장소 데이터는 다음 기준을 적용한다.

| 항목 | 기준 |
|---|---|
| 장소명 | 장소명이 없는 데이터는 1차 import에서 제외한다. |
| 위도 | 숫자로 변환 가능한 값만 사용한다. |
| 경도 | 숫자로 변환 가능한 값만 사용한다. |
| 좌표 범위 | 대한민국 범위에서 벗어난 좌표는 제외한다. |
| 주소 | 도로명 주소 또는 지번 주소 중 하나 이상 있으면 저장한다. |
| 데이터 기준일 | 원본 데이터에 기준일이 있으면 저장한다. |
| 원본 데이터 | 정제 후에도 raw_data에 원본 행 정보를 저장한다. |
| 중복 | 장소명, 주소, 좌표를 기준으로 중복 여부를 판단한다. |

---

## 4. 좌표 정제 기준

지도 표시를 위해 위도와 경도는 필수값으로 사용한다.

초기 구현에서는 좌표가 있는 데이터만 우선 import한다.

| 상태 | 처리 방식 |
|---|---|
| 위도/경도 모두 있음 | import 대상 |
| 위도 또는 경도 하나만 있음 | import 제외 |
| 위도/경도 없음, 주소 있음 | 주소 변환 후보로 보류 |
| 위도/경도 없음, 주소도 없음 | 제외 |
| 대한민국 범위 밖 좌표 | 제외 |

대한민국 좌표 범위는 1차적으로 아래 기준을 사용한다.

```txt
위도: 33 ~ 39
경도: 124 ~ 132
```

---

## 5. 중복 데이터 판단 기준

중복 데이터는 다음 기준을 조합하여 판단한다.

| 기준 | 설명 |
|---|---|
| 장소명 | 공백 제거 후 비교 |
| 주소 | 도로명 주소 또는 지번 주소 비교 |
| 좌표 | 위도/경도 소수점 일정 자리까지 비교 |
| 카테고리 | 같은 카테고리 내 중복 우선 판단 |
| source_file | 같은 파일 내 중복 여부 확인 |

초기 구현에서는 무리하게 모든 중복을 제거하지 않고, 명확히 같은 데이터만 제외한다.

## 6. 데이터별 사용 컬럼

### 6.1 공중화장실

| 사용 목적 | 원본 컬럼 |
|---|---|
| 장소명 | 화장실명 |
| 카테고리 | 공중화장실 고정 |
| 지번 주소 | 소재지지번주소 |
| 도로명 주소 | 소재지도로명주소 |
| 위도 | WGS84위도 |
| 경도 | WGS84경도 |
| 개방 시간 | 개방시간, 개방시간상세 |
| 장애인 편의 | 장애인용 대변기/소변기 수 |
| 어린이 이용 | 어린이용 대변기 수 |
| 비상벨 | 비상벨설치여부 |
| CCTV | 화장실입구CCTV설치유무 |
| 관리기관 | 관리기관명 |
| 기준일 | 데이터기준일자 |

#### 공중화장실 처리 기준

- 좌표가 있는 데이터만 1차 import한다.
- 좌표가 없고 주소가 있는 데이터는 추후 주소 변환 후보로 분리한다.
- 장애인용 또는 어린이용 시설 수가 1 이상이면 관련 태그를 부여한다.
- 개방시간에 24시간이 포함된 경우 `24시간` 태그를 부여한다.

---

### 6.2 무료 와이파이

| 사용 목적 | 원본 컬럼 |
|---|---|
| 장소명 | 설치장소명 |
| 상세 위치 | 설치장소상세 |
| 카테고리 | 무료와이파이 고정 |
| 시도 | 설치시도명 |
| 시군구 | 설치시군구명 |
| 시설 구분 | 설치시설구분명 |
| 도로명 주소 | 소재지도로명주소 |
| 지번 주소 | 소재지지번주소 |
| 위도 | WGS84위도 |
| 경도 | WGS84경도 |
| 제공사 | 서비스제공사명 |
| SSID | 와이파이SSID |
| 관리기관 | 관리기관명 |
| 기준일 | 데이터기준일자 |

#### 무료 와이파이 처리 기준

- 좌표가 있는 데이터는 1차 import 대상으로 사용한다.
- `와이파이`, `무료`, `인터넷사용` 태그를 기본 부여한다.
- 설치시설구분명과 설치장소명을 활용하여 보조 태그를 부여할 수 있다.
- 단, `노트북작업가능`, `조용함`, `콘센트있음`은 확정 태그로 부여하지 않는다.

---

### 6.3 도시공원

| 사용 목적 | 원본 컬럼 |
|---|---|
| 장소명 | 공원명 |
| 카테고리 | 도시공원 고정 |
| 공원 유형 | 공원구분 |
| 도로명 주소 | 소재지도로명주소 |
| 지번 주소 | 소재지지번주소 |
| 위도 | 위도 |
| 경도 | 경도 |
| 면적 | 공원면적 |
| 운동시설 | 공원보유시설(운동시설) |
| 유희시설 | 공원보유시설(유희시설) |
| 편익시설 | 공원보유시설(편익시설) |
| 교양시설 | 공원보유시설(교양시설) |
| 관리기관 | 관리기관명 |
| 기준일 | 데이터기준일자 |

#### 도시공원 처리 기준

- 좌표가 있는 데이터는 1차 import 대상으로 사용한다.
- `공원`, `산책`, `휴식`, `야외` 태그를 기본 부여한다.
- 공원구분과 보유시설 컬럼을 활용하여 추가 태그를 부여한다.
- `야경좋음`, `조용함`, `데이트좋음` 등은 데이터만으로 확정하지 않는다.

---

### 6.4 흡연구역

흡연구역 데이터는 파일마다 컬럼 구조와 품질 차이가 있으므로 개별 파일 단위로 정제 기준을 적용한다.

| 사용 목적 | 가능한 원본 컬럼 |
|---|---|
| 장소명 | 시설명, 설치위치, 장소명 등 |
| 카테고리 | 흡연구역 고정 |
| 주소 | 주소, 도로명주소, 지번주소 등 |
| 위도 | 위도, latitude 등 |
| 경도 | 경도, longitude 등 |
| 시설 형태 | 시설형태, 흡연실형태 등 |
| 관리 여부 | 관리여부 |
| 기준일 | 데이터기준일자 |

#### 흡연구역 처리 기준

- 좌표가 있는 데이터부터 우선 import한다.
- 통계성 데이터는 장소 데이터로 사용하지 않는다.
- 사용자 제보 성격의 JSON 데이터는 출처와 사용 조건을 확인한 뒤 사용 여부를 결정한다.
- `흡연`, `흡연구역` 태그는 기본 부여한다.
- 실내, 실외, 개방형, 폐쇄형 정보가 명확한 경우에만 관련 태그를 부여한다.

## 7. import 제외 기준

다음 데이터는 초기 import에서 제외한다.

| 제외 기준 | 설명 |
|---|---|
| 장소명 없음 | 사용자가 장소를 인식하기 어려움 |
| 위도/경도 없음 | 지도 표시 불가 |
| 좌표 변환 실패 | 거리 계산 불가 |
| 대한민국 범위 밖 좌표 | 잘못된 좌표 가능성 |
| 통계성 데이터 | 장소 단위 데이터가 아님 |
| 출처 불명 데이터 | 사용 조건 확인 필요 |
| 중복이 명확한 데이터 | 동일 장소 반복 저장 방지 |

## 8. 정제 실패 데이터 처리

정제 실패 데이터는 바로 삭제하지 않고 로그로 남긴다.

예시 로그 항목은 다음과 같다.

| 항목 | 설명 |
|---|---|
| source_file | 원본 파일명 |
| source_row_id | 원본 행 번호 |
| reason | 제외 사유 |
| raw_data | 원본 데이터 |

정제 실패 데이터는 추후 주소 보정, 컬럼 보정, 출처 확인 후 재처리할 수 있다.

---

## 9. 태그 자동 부여와의 연결

데이터 정제 이후 장소가 import되면, 해당 장소의 카테고리와 원본 컬럼 값을 기준으로 태그를 자동 부여한다.

태그 부여 방식은 다음 문서에서 관리한다.

```txt
docs/04_recommendation/tagging-rule.md
```

정제 단계에서는 장소 데이터의 사용 가능 여부를 판단하고, 태그 부여 단계에서는 해당 장소가 어떤 상황에 추천될 수 있는지 판단한다.

---

## 10. 현재 단계에서 하지 않는 작업

현재는 DB 모델이 확정되지 않았으므로 다음 작업은 진행하지 않는다.

- 원본 CSV 직접 수정
- 모든 CSV를 하나의 파일로 병합
- fixtures 생성
- 좌표 없는 데이터 대량 지오코딩
- 중복 데이터 완전 제거
- DB import 실행

해당 작업은 Django 프로젝트 생성 및 모델 작성 이후 진행한다.
