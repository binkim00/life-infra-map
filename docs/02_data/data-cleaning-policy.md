# 데이터 정제 기준

## 1. 문서 목적

본 문서는 상황 기반 생활 장소 추천 지도 서비스에서 외부 데이터를 수집한 뒤, 추천 서비스에서 사용할 수 있도록 정제하는 기준을 정의합니다.

현재 프로젝트에서는 공공데이터 CSV, 자체 수집 JSON, 지도 API 검색 결과, 블로그 검색 결과 기반 후보 태그를 함께 검토하고 있습니다. 모든 데이터를 같은 방식으로 저장하지 않고, 실제 장소 데이터와 외부 후보 태그를 분리해서 관리합니다.

---

## 2. 데이터 사용 단계

| 단계 | 설명 | 예시 |
|---|---|---|
| raw | 원본 데이터 | 공공데이터 CSV, API 원본 JSON |
| cleaned | 공통 Place 구조로 정제한 데이터 | `ExData/Cleaned/*.json` |
| place_tag_seed | DB의 PlaceTag로 넣을 태그 seed | `Test/apiTest/tag/*/*_place_tag_seed.json` |
| external_place_tag_seed | Place에 저장하지 않는 외부 장소 후보 태그 | 카페 ExternalPlaceTag seed |
| import_data | 실제 import 명령어가 읽을 통합 폴더 | 다음 작업에서 생성 예정 |

원본 데이터는 수정하지 않고 보존합니다. DB import에 사용할 파일은 다음 단계에서 `backend/recommendations/fixtures/import_data/` 아래로 복사본을 모아 관리합니다.

---

## 3. 공통 Place 정제 기준

모든 장소 데이터는 최종적으로 아래 기준을 적용합니다.

| 항목 | 기준 |
|---|---|
| 장소명 | 장소명이 없는 데이터는 1차 import 대상에서 제외 |
| 카테고리 | 서비스에서 사용하는 표준 카테고리 문자열로 저장 |
| 위도/경도 | 숫자로 변환 가능한 값만 사용 |
| 좌표 범위 | 대한민국 범위에서 벗어난 좌표는 제외 |
| 주소 | 도로명 주소 또는 지번 주소 중 하나 이상 있으면 저장 |
| 상세 위치 | 원본에 있으면 `detail_location`에 저장 |
| 기준일 | 원본 데이터에 기준일이 있으면 `source_updated_at`에 저장 |
| 출처 | `source`, `source_name`, `external_id`로 추적 |
| 원본 | 정제 후에도 `raw`에 원본 행 정보를 저장 |
| 중복 | 기본 기준은 `source + external_id` |

좌표 정제 1차 기준은 다음과 같습니다.

```text
위도: 33 ~ 39
경도: 124 ~ 132
```

## 4. 태그 정제 기본 원칙

### 4.1 기본 태그 제거

`Place.category`만으로 알 수 있는 기본 태그는 `PlaceTag`로 저장하지 않습니다.

예시:

```text
주차장
공원
도시공원
해수욕장
바다
공중화장실
생활편의
쉼터
무료와이파이
흡연구역
```

### 4.2 추천/필터에 쓸 수 있는 세부 속성만 유지

원본 필드, 키워드 규칙, 블로그 검색 결과에서 나온 태그 중 추천/필터에 실제로 쓰는 정보만 유지합니다.

예시:

```text
무료주차
장애인화장실있음
기저귀교환대있음
냉방시설있음
야간운영후보
산책좋음
야경
드라이브목적지
실내흡연실
부스형흡연구역
```

### 4.3 정보 존재 여부 태그 제거

단순히 어떤 정보가 존재한다는 뜻만 가진 태그는 추천에 직접 쓰기 어려우므로 제거합니다.

제거 예시:

```text
오물처리방식정보있음
남녀화장실정보있음
연락처있음
개방시간정보있음
운영시간정보있음
수용인원정보있음
면적정보있음
```

## 5. 카테고리별 정제 기준

### 5.1 공중화장실

| 사용 목적 | 원본 컬럼 예시 |
|---|---|
| 장소명 | 화장실명 |
| 카테고리 | `toilet` 고정 |
| 주소 | 소재지도로명주소, 소재지지번주소 |
| 위도/경도 | WGS84위도, WGS84경도 |
| 개방 시간 | 개방시간, 개방시간상세 |
| 장애인 편의 | 장애인용 대변기/소변기 수 |
| 어린이 이용 | 어린이용 대변기 수 |
| 비상벨 | 비상벨설치여부 |
| CCTV | 화장실입구CCTV설치유무 |
| 기준일 | 데이터기준일자 |

처리 기준:

- 좌표가 있는 데이터만 1차 import 후보로 사용합니다.
- `공중화장실`, `생활편의` 기본 태그는 제거합니다.
- 장애인화장실, 기저귀교환대, 비상벨, CCTV, 24시간개방후보 등 실제 이용 편의 태그만 유지합니다.
- 노이즈 태그는 제거하고 원본 정보는 `raw`에 보존합니다.

---

### 5.2 무료와이파이

| 사용 목적 | 원본 컬럼 예시 |
|---|---|
| 장소명 | 설치장소명 |
| 상세 위치 | 설치장소상세 |
| 카테고리 | `free_wifi` 고정 |
| 주소 | 소재지도로명주소, 소재지지번주소 |
| 위도/경도 | WGS84위도, WGS84경도 |
| 시설 구분 | 설치시설구분명 |
| 제공사 | 서비스제공사명 |
| SSID | 와이파이SSID |
| 기준일 | 데이터기준일자 |

처리 기준:

- 좌표가 있는 데이터는 Place import 후보로 사용합니다.
- 무료와이파이는 위치 데이터 자체가 핵심이므로 `PlaceTag` seed를 생성하지 않습니다.
- `무료와이파이`, `와이파이`, `인터넷사용` 같은 기본 태그는 저장하지 않습니다.
- 무료와이파이 데이터만으로 `노트북작업가능`, `조용함`, `콘센트있음`은 확정하지 않습니다.

---

### 5.3 도시공원

| 사용 목적 | 원본 컬럼 예시 |
|---|---|
| 장소명 | 공원명 |
| 카테고리 | `city_park` 또는 현재 모델 기준 카테고리 문자열 |
| 주소 | 소재지도로명주소, 소재지지번주소 |
| 위도/경도 | 위도, 경도 |
| 공원 유형 | 공원구분 |
| 면적 | 공원면적 |
| 시설 정보 | 운동시설, 유희시설, 편익시설, 교양시설 |
| 기준일 | 데이터기준일자 |

처리 기준:

- 좌표가 있는 데이터는 Place import 후보로 사용합니다.
- `공원`, `도시공원`처럼 카테고리만으로 알 수 있는 태그는 제거합니다.
- 공원구분, 보유시설, 면적, 블로그 기반 후보 태그를 활용합니다.
- `조용함`, `데이트좋음` 등은 공공데이터만으로 확정하지 않습니다.

---

### 5.4 흡연구역

흡연구역 데이터는 위치 기반 추천이 중심입니다.

| 사용 목적 | 가능한 원본 컬럼 |
|---|---|
| 장소명 | 시설명, 설치위치, 장소명 등 |
| 카테고리 | `smoking_area` 고정 |
| 주소 | 주소, 도로명주소, 지번주소 등 |
| 위도/경도 | 위도, 경도, latitude, longitude |
| 시설 형태 | 시설형태, 흡연실형태, 실내외구분, facility_type 등 |
| 기준일 | 데이터기준일자 |

처리 기준:

- 좌표가 있는 데이터부터 우선 import합니다.
- 통계성 데이터는 장소 데이터로 사용하지 않습니다.
- `흡연`, `흡연구역`, `흡연가능` 기본 태그는 저장하지 않습니다.
- 실내/실외/부스형/개방형이 명확한 경우에만 세부 유형 태그를 저장합니다.
- `관리:기관명`, `상태:...`, `제보유형:...`은 PlaceTag가 아니라 원본 메타데이터로 봅니다.

---

### 5.5 주차장

| 사용 목적 | 원본 컬럼 예시 |
|---|---|
| 장소명 | 주차장명 |
| 카테고리 | `parking` 고정 |
| 주소 | 소재지도로명주소, 소재지지번주소 |
| 위도/경도 | 위도, WGS84위도, 경도, WGS84경도 |
| 주차장 구분 | 노상/노외/부설 등 |
| 운영 시간 | 평일/토요일/공휴일 운영시간 |
| 요금 정보 | 유료/무료, 기본요금, 추가요금 |
| 기준일 | 데이터기준일자 |

처리 기준:

- 좌표가 있는 데이터는 Place import 후보로 사용합니다.
- `주차장` 기본 태그는 제거합니다.
- 무료/유료, 공영/민영, 운영시간 후보, 장애인주차구역 여부 등은 세부 태그로 사용합니다.
- 실시간 주차 가능 대수는 초기 구현 범위에 포함하지 않습니다.
- 현재 주차장 seed에는 `category_rule`이 일부 남아 있으므로 최종 import 전 의미 확인이 필요합니다.

---

### 5.6 해수욕장

처리 기준:

- 좌표가 있는 데이터만 Place import 후보로 사용합니다.
- `해수욕장`, `바다`, `물놀이`처럼 카테고리 또는 기본 목적을 나타내는 태그는 제거했습니다.
- 해변 종류, 해변 길이, 블로그 기반 후보 태그를 활용합니다.
- 좌표가 없는 데이터는 스킵합니다.

---

### 5.7 쉼터

처리 기준:

- 재난안전데이터공유플랫폼 무더위쉼터 API 수집 결과를 사용합니다.
- 좌표가 있는 데이터는 Place import 후보로 사용합니다.
- `쉼터` 기본 태그와 정보 존재 여부 태그는 제거했습니다.
- `무더위쉼터`는 현재 seed에 남아 있으나 카테고리 성격이 강하므로 최종 import 전 제외 여부를 다시 확인합니다.
- 냉방시설, 실내/야외, 운영시간 후보, 수용인원, 숙박 가능 후보 등은 추천/필터에 활용할 수 있습니다.

---

### 5.8 카페 후보

카페는 현재 Place로 직접 저장하지 않고, 카카오 Local API 검색 결과와 매칭할 수 있는 외부 장소 태그 후보로 관리합니다.

처리 기준:

- 카카오 place id 기준으로 외부 후보를 구분합니다.
- 블로그 기반 태그는 확정 정보가 아니라 후보 정보입니다.
- 카카오/지도 리뷰를 무단 크롤링해서 저장하지 않습니다.
- `ExternalPlaceTag` 모델 추가 후 import 대상으로 사용합니다.

## 6. 다음 데이터 작업

다음 작업은 정제 결과를 import 기준 폴더로 모으는 것입니다.

```text
backend/recommendations/fixtures/import_data/
├─ places/
├─ place_tags/
└─ external_place_tags/
```

원본 산출물은 유지하고, import용 복사본만 위 폴더에 모읍니다.
