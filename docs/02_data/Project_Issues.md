## 데이터 수집 이슈 메모
### 1. 관광지 데이터 범위
- 관광지 전체를 쓰면 서비스 방향이 커질 수 있음
- 산책, 드라이브, 힐링 목적지 후보로 쓸 수 있는 장소만 선별 예정
- 숙박, 축제, 장거리 여행 중심 데이터는 제외 검토

### 2. 카페 데이터 확보
- 카페는 추천 서비스에서 중요하지만 공공데이터로 확보가 어려움
- 지도 API로 주변 카페 후보를 실시간 검색하고, 추천 태그는 사용자 제보/초기 소량 데이터로 보완 예정
- 지도 API 결과를 대량 저장하는 방식은 약관 확인 필요

### 3. 지도 API 활용
- 저장용 데이터가 아니라 실시간 검색, 장소 선택, 좌표 보정, 외부 후보 표시 용도로 활용 예정
- API별 저장/캐싱 정책 확인 필요

### 4. 산책/드라이브/힐링 데이터
- 생활 인프라 데이터만으로는 상황형 추천 매력이 부족함
- 관광지 표준데이터, TourAPI, 지자체 명소/야경 데이터를 보조 데이터로 검토
- 산책, 전망, 야경, 공원, 강변, 주차 가능한 장소 중심으로 필터링 예정

### 방문자 리뷰 키워드 크롤링 테스트 결과

네이버 플레이스 방문자 리뷰 페이지 상단의 대표 키워드는 일부 추출 가능했다.
다만 해당 키워드는 외부 지도 서비스에서 이미 제공하는 장소 평가 정보이며, 이를 장소별로 저장해 태그화할 경우 외부 지도 정보의 재가공에 가까워진다.
또한 대표 키워드만으로는 조용함, 콘센트 있음, 와이파이 있음, 노트북 작업 가능, 흡연실 있음과 같은 서비스 핵심 추천 태그를 충분히 확보하기 어렵다.
따라서 외부 방문자 리뷰 키워드 기반 태그화는 핵심 데이터 수집 방식으로 사용하지 않고, 가능성 검토 수준으로 정리한다.

### 태그 수집 및 생성 방식 검토 필요

상황 기반 추천을 위해서는 장소별 태그가 필요하지만, 태그를 어떤 방식으로 확보하고 관리할지는 추가 검토가 필요하다.

현재까지 검토한 방식은 다음과 같다.

- 외부 데이터의 카테고리 기반 기본 태그 자동 부여
- 지도 API 장소 정보에 카테고리/장소명 기반 후보 태그 부여
- 공공데이터와의 거리 계산을 통한 관계 기반 태그 생성
  - 예: 흡연구역 근처, 주차장 근처, 공공 와이파이 근처
- 방문자 리뷰 키워드 기반 태그화 가능성 검토
- AI 기반 추천 태그 후보 생성

다만 방문자 리뷰 키워드 기반 태그화는 외부 지도 서비스에서 이미 제공하는 정보를 재가공하는 형태가 될 수 있고, 약관 및 최신성 문제도 있어 핵심 데이터 수집 방식으로 확정하기 어렵다.

또한 조용함, 콘센트 있음, 와이파이 있음, 흡연실 있음, 노트북 작업 가능처럼 변동 가능성이 높은 태그는 한 번 수집해 저장하더라도 최신성을 유지하기 어렵다.

따라서 태그는 단순히 많이 수집하는 것보다, 출처, 신뢰도, 확인일, 상태값을 함께 관리하는 방향으로 설계할 필요가 있다.
