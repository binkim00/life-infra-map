# docs 폴더 구성

본 폴더는 상황 기반 생활 장소 추천 지도 서비스의 기획, 데이터 수집, 추천 설계, 구현 진행 상황을 정리하는 문서 폴더입니다.

## 폴더 구조

| 폴더명 | 용도 |
|---|---|
| `00_project` | 프로젝트 전체 설명, 서비스 방향, 로드맵 |
| `01_progress` | 일차별 진행 상황, 개인 할 일, 회의/작업 기록 |
| `02_data` | 데이터 출처, 수집 이슈, 정제 기준, 공통 스키마 |
| `03_planning` | 요구사항, ERD, Use Case, 화면 설계 |
| `04_recommendation` | 태그 목록, 태그 부여 규칙, 추천 시나리오, 추천 로직 |
| `99_archive` | 예전 버전, 폐기한 초안, 참고용 문서 |
| `Day 폴더` | 관통 프로젝트 진행 날짜별 파일 및 문서 |

## 현재 문서화 기준

현재 프로젝트는 단순 지도 검색 서비스가 아니라, 사용자의 위치와 상황을 기반으로 생활 장소를 추천하고 지도에서 확인하는 서비스입니다.

문서 작성 시 다음 기준을 유지합니다.

- 지도 API는 장소 후보 조회, 좌표 확인, 지도 표시를 위한 보조 수단으로 사용합니다.
- 추천의 핵심은 장소 카테고리, 태그, 거리, 최신성, 신뢰도, 데이터 출처를 조합하는 규칙 기반 추천입니다.
- 공공데이터와 외부 API 데이터는 실제 확보 가능한 장소 정보 중심으로 사용합니다.
- 블로그 검색 결과 기반 태그는 확정 정보가 아니라 후보 태그로 관리합니다.
- AI는 장소 정보를 임의 생성하지 않고, 자연어 입력을 장소 검색 frame으로 정리하고 후보 적합성을 판단하는 보조 역할로만 사용합니다.
- 추천 검색은 AI-first 백엔드 오케스트레이터를 기준으로 처리하며, 일반 지도 검색은 AI 해석 없이 별도 화면에서 제공합니다.

## 현재 구현/수집 반영 상태

- Django + DRF 백엔드와 Vue 프론트엔드 기본 구조를 생성했습니다.
- 카카오 지도와 추천 결과 마커 표시 흐름을 테스트했습니다.
- 흡연구역 데이터는 JSON 직접 조회 방식에서 DB 조회 방식으로 전환했습니다.
- `Place`, `Tag`, `PlaceTag` 기반 태그 연결 구조를 사용합니다.
- 카카오 검색 결과와 DB `Place.external_id`를 매칭해 저장 태그/추천 정보를 보강하는 흐름을 구현했습니다.
- 카카오 검색 결과는 저장하지 않고 화면 표시용 후보로 사용합니다.
- AI 추천 검색 결과는 backend source label 기준으로 `DB추천`, `카카오 후보`, `웹 참고`를 구분합니다.
- 홈 화면은 AI-first 자연어 추천 검색을 처리합니다.
- `/map` 지도 탭은 DB에 저장된 장소와 Kakao 키워드 결과를 AI 해석 없이 그대로 검색하는 일반 지도 페이지입니다.
- AI 추천 검색은 백엔드 `/api/recommendations/ai-search/`에서 frame 생성, 후보 수집, evidence ranker/reranker 흐름으로 처리합니다.
- 일반 지도 검색은 백엔드 `/api/recommendations/map-search/`에서 DB `Place`와 Kakao 장소 후보를 함께 반환합니다.
- 장소/태그 제보는 관리자 승인 후 DB `Place` 또는 `PlaceTag`에 반영되고, 일반 지도 검색에서 확인할 수 있습니다.
- 카페 태그 수집 결과를 Django fixture 형태로 준비했습니다.
- 관광지 블로그 기반 태그 후보 생성 스크립트와 결과 파일을 추가했습니다.
- 진행 상황은 `docs/01_progress/PROGRESS.md`에 일차별로 기록합니다.
