# 주소 추출·비교 변경 검토 — 2026-10-22

후속 상태: 아래는 보완 전 검토 기록이다. 사용자 요청에 따라 발견 사항을 로컬에서 수정했고 관련 39개 테스트, 저장 반례 11개 보류, 실제 표본의 기존 6/24 주소 일치 유지를 확인했다. 상세는 `docs/ADDRESS_MATCHING_LOCAL_FIX_2026-10-22.md`의 검토 후 보완 기록을 참조한다. 운영 반영은 하지 않았다.

## 결론과 범위

현재 수정안을 안전하다고 판단할 수 없다. 관련 테스트 34개는 통과했지만 주소 비교의 누락 3종과 기존 지점명 검증의 한계를 재현했다. 수정 전에는 보류되던 가상 입력 8개가 현재 `assess_content()`에서 `approve`로 바뀐다. 아래 문제의 보완과 회귀 테스트가 필요하다.

이번 작업은 로컬 diff·테스트 검토다. 구현 및 테스트 소스는 수정하지 않았다. 운영 접속·배포·설정 변경·데이터 변경·보류 해제는 하지 않았다. 실제 보류 361건에서 오승인이 발생했다는 결과가 아니라, 가상 입력으로 확인한 코드 동작이다.

## 검증 방법

- `recommendations.test_address_matching`, `recommendations.test_automatic_content_review`, `recommendations.test_codex_content_review`: **34개 통과**. `config.test_settings`의 SQLite 메모리 테스트 DB만 사용했다. 기존 테스트의 apply/restore 출력도 이 가상 DB에 한정된다.
- 현재 `automatic_content_review.py`와 Git `HEAD`의 같은 파일을 각각 메모리에 로드해 동일한 미저장 모델 객체를 전달했다. 다른 의존 모듈은 동일한 현재 작업 트리 것을 사용하므로, 비교 대상은 이 파일 변경의 효과다.
- 추가 반례에서는 DB cursor 및 네트워크 socket 접근을 예외로 차단했다. `matching_address()`와 `assess_content()`만 호출했고 실제 저장 함수는 호출하지 않았다.
- 재현 입력, 제목, 등록 주소, 전후 판정, 기준 커밋 및 현재 소스 SHA-256: `runtime/address-matching-review-20261022/results.json`.

## 발견 사항

### 1. [P1] 줄바꿈 이후 다른 층·호수를 무시해 기존 보류가 승인으로 바뀜

위치: `backend/recommendations/services/automatic_content_review.py:118-124`, `165-170`.

`_address_units()`가 주소 뒤 40글자만 보고 첫 줄바꿈·문장부호에서 자른다. 비교할 층/호가 추출되지 않으면 충돌이 없는 것으로 통과한다.

- 등록 주소: `부산 중구 중앙대로 100 1층`
- 본문: `부산 중구 중앙대로 100\n2층 테스트커피 서면점에는 콘센트가 있어요.`
- 수정 전: `hold`; 현재: `approve`.
- 등록 `101호`와 본문 다음 줄 `102호`도 동일하게 재현된다. 짧은 주소에 한정된 문제가 아니다.
- 등록 `1층`과 본문 `B1`도 현재 통과한다. 숫자 뒤 `층|호` 이외 표기는 추출하지 않기 때문이다.

주소 블록의 줄바꿈을 보존해 상세 주소를 대조하고, 명시된 상세 주소를 해석하지 못한 경우 확인 필요 상태로 남겨야 한다. 기존 테스트는 같은 줄의 `2층`, `지하 1층`, `102호` 충돌만 다룬다.

### 2. [P1] 쉼표·괄호·줄바꿈으로 행정구역 충돌 검사를 우회함

위치: `automatic_content_review.py:86-107`, `152-157`.

행정구역은 도로명 바로 앞의 공백 구분 토큰만 검사한다. `중구,`나 `중구(중앙동)`을 만나면 즉시 중단하고, 줄바꿈 앞의 지역은 잘라 버린다. 그 결과 지역 정보가 빈 값이 되고 충돌 검사를 통과한다.

- 등록: `부산 중구 중앙대로 2`
- 본문: `대구 중구, 중앙대로 2 테스트커피 서면점에는 콘센트가 있어요.`
- 제목: `부산 테스트커피 서면점 후기`
- 수정 전: `hold`; 현재: `approve`.
- `대구 중구\n중앙대로 2`도 같다. 같은 부산 내에서 등록 `부산진구`와 본문 `중구(중앙동)`도 통과한다.

기존 후속 지역 검사도 제목에 기대 지역이 있으면 본문의 다른 지역을 막지 못한다. 주소 블록의 지역 표기를 정규화하고, 명시된 충돌을 지역 정보 부재로 취급하지 않아야 한다. 현재 테스트에는 동일 주소의 구두점·개행 변형이 없다.

긴 주소 `중앙대로 100`에서는 같은 결함이 수정 전에도 있었다. 따라서 모든 지역 오판이 이번에 새로 생겼다고 볼 수 없으나, 짧은 주소 허용으로 잘못 승인되는 입력 범위가 확대됐다.

### 3. [P1] 다른 도로로 이전한 문장에서 옛 주소만 일치해 통과함

위치: `automatic_content_review.py:137-150`.

본문의 주소 후보를 등록 주소의 도로명으로 먼저 제한한다. 따라서 같은 도로의 다른 건물번호는 충돌로 처리하지만, 다른 도로명인 새 주소는 비교 대상에 포함하지 않는다.

- 등록: `부산 중구 중앙대로 2`
- 본문: `테스트커피 서면점은 부산 중구 중앙대로 2에서 부산 중구 광복로 10으로 이전했습니다. 새 매장에는 콘센트가 있어요.`
- 수정 전: `hold`; 현재: `approve`.
- 새 주소가 같은 도로의 `중앙대로 21`이면 현재도 `hold`다.

이전 또는 복수 주소가 명시된 문장은 전체 주소 후보와 문맥을 먼저 확인해야 한다. 현재 테스트의 같은 도로 내 번호 변경만으로 이전 방어가 검증되지는 않는다. 이 문제 역시 긴 주소에서는 기존에도 재현되며, 이번 지원 확장으로 짧은 주소에도 영향을 준다.

### 4. [P2, 기존 한계] 지점명 전체가 다른 이름의 접두어여도 통과함

위치: `automatic_content_review.py:268`의 변경되지 않은 이름 부분 문자열 검사.

- 등록 이름: `테스트커피 서면점`
- 제목 및 본문 이름: `테스트커피 서면점2호점`
- 주소: 모두 `부산 중구 중앙대로 2`
- 수정 전: `hold`; 현재: `approve`.

긴 주소 `중앙대로 100`으로 바꾸면 수정 전에도 승인된다. 지점명 검사를 이번에 삭제하거나 약화한 것은 아니지만, 이 기존 검사를 그대로 두면 새로 지원되는 주소에서 다른 지점을 충분히 차단한다고 할 수 없다. 새로운 테스트는 `서면점`과 `연산점`처럼 서로 포함되지 않는 이름만 다룬다. 별도 지점명이 등록 이름을 포함하는 사례도 경계와 지점 식별을 검사해야 한다.
