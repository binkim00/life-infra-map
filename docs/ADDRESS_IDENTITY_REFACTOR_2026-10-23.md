1. 이전 기대 판정 294개와 최신 검토 입력 62개를 합친 합성 입력 **356개**를 `backend/recommendations/fixtures/address_identity_acceptance.json`에 고정한다. 구현에 맞춰 기대값을 바꾸지 않는다. 결과는 주소 함수만이 아니라 최종 `assess_content()` 판정으로 비교한다.
2. 기존 관련 테스트 97개를 유지한다. 정상 붙임·동등 표기·확인된 범위의 약식 반복을 통과시키고, 다른 지역·건물번호·동·관·호실·지점, 미해석 범위와 필수 상세 미확인은 보류한다. 반대 주장 등 기존 reject 기준도 유지한다.
3. 주소 처리 모듈은 DB/네트워크에 의존하지 않는다. 위치/기본 주소 비교, 상세 토큰 해석, 이름/지점 확인, 최종 판단을 분리한다. 해석 결과는 구성 요소·원문 범위·미해석 사유를 보존한다. 미해석을 정보 부재로 바꾸지 않는다.
4. 제목과 본문은 같은 상세 해석기와 호점 정규화를 사용한다. 화장실 층은 매장 상세로 쓰지 않고 건물 충돌과 미해석 상태는 남긴다. 한 개의 온전한 주소 언급에서 필수 상세가 확인돼야 한다.
5. 기존 저장 주소 표본 24개는 로컬 보관 입력으로 재검증한다. 새 DB 조회 없이 실행하며 상태를 변경하지 않는다. 저장/복구 테스트는 SQLite 메모리 DB 전용이다.
6. 하나의 관련 테스트 실행으로 기존 회귀 테스트와 고정 입력 전체를 검사한다. 구조 검사, 시스템 검사와 diff 검사를 통과하고 최종 해시/명령/결과를 기록하면 이번 로컬 작업을 완료한다. 운영 접속·배포·데이터 변경·보류 해제·커밋/푸시는 범위 밖이다.

위 기준은 구현 전에 기록했다. 모든 자연어 표현이나 운영 정확도를 보장하는 기준은 아니다.


## 최종 구조

- `services/address_identity.py`: 한국어 주소의 정규화/어휘, 기본 주소·지역 비교, 이름·호점 정체성, 제목 문맥 처리. 기존 도로명/지번 및 지역 충돌 비교는 유지한다.
- `services/address_details.py`: 순서대로 읽는 상세 해석기. `DetailToken`에 항목·값·정규화된 원문 위치를, `ParseIssue`에 미해석 사유·구간을 보존한다. `ParsedDetails`는 missing/parsed/unresolved 상태와 읽기 중단 문맥을 구분한다. 필수 상세 확인은 최종 비교에서 수행한다.
- 층/호실을 읽은 뒤 조사로 이어지는 후속 상세도 읽는다. 일반 시설 설명은 매장 주소 문맥과 구별한다. 이름 뒤 접두어를 허용 여부의 근거로 쓰던 `_UNIT_END`/`_UNIT_START`는 제거했다. 정규식은 어휘 인식에 사용하며 완전한 상세 해석과 비교를 대신하지 않는다.
- 숫자 호점은 공통 정규화로 비교한다. 같은 번호의 직접 제목 반복도 허용하고 다른 번호는 보류한다.
- `services/automatic_content_review.py`: 새 순수 모듈 호출을 연결한다. 기존 `assess_content`, 반대 주장, 원문 귀속, 저장·복구 관련 함수 본문은 v15와 AST 기준 동일하다. 정책 식별자는 `content-structured-v1-20261023`이다.
- 테스트는 기존 97개를 유지하고 `test_address_identity.py`를 추가했다. 고정 입력 356개와 상태/구간/문맥 검사, 조사·공백·호실 동등 표기의 최종 판정 72개 조합을 같은 실행에서 검사한다. 실제 장소·근거 DB를 수정하지 않는 합성 입력 fixture다.
