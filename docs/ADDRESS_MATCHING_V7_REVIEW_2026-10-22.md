# content-v7 최종 diff 및 층·호수 조건 검토 — 2026-10-22

후속 상태: 아래 6종은 같은 날짜 content-v8 로컬 보완 및 회귀 테스트에 반영했다. 직전 입력 16개가 기대 판정대로 통과했으며, 구현·검증 요약은 `docs/ADDRESS_MATCHING_LOCAL_FIX_2026-10-22.md`의 content-v8 절에 있다. 아래 내용은 수정 전 발견 기록이며 운영 반영을 뜻하지 않는다.

## 결론

추가 보완이 필요하다. 특히 층·호수 검사는 **같은 정보를 이미 확인한 정상 근거도 보류**하면서, **등록 상세 주소를 읽지 못한 경우에는 오히려 다른 층·호수를 승인**하는 비대칭이 있다. 건물 동·본관/별관도 비교하지 않는다.

현재 관련 테스트 48개는 모두 통과했다. 추가 가상 입력 16개 중 예상과 다른 승인 7개, 예상과 다른 보류 6개를 확인했고 대조 입력 3개는 예상대로였다. 오류는 아래 6종으로 분류했다. 실제 운영 근거의 오류 건수나 오류율은 아니다.

검토 범위는 로컬 코드·테스트다. 구현 및 테스트 소스를 변경하지 않았고 운영 접속·배포·설정 변경·데이터 변경·보류 해제도 하지 않았다.

## 검증 방법

- 검토 대상 소스 SHA-256이 직전 content-v7 검증 기록과 일치함을 확인했다.
- `test_address_matching`, `test_automatic_content_review`, `test_codex_content_review` 총 48개 테스트 재실행 통과. 기존 저장/복구 테스트는 SQLite 메모리 테스트 DB만 사용했다.
- 새 입력은 DB cursor 및 네트워크 socket 접근을 차단하고 미저장 객체에 순수 판정 함수만 적용했다.
- 입력, 기대/실제 판정, 주소별 추출 층·호수, 소스 해시: `runtime/address-matching-v7-review-20261022/results.json`.
- 아래 사례의 공통 도로 주소는 `부산 중구 중앙대로 100`, 등록 이름은 `테스트커피 서면점`, 근거는 해당 이름의 직접 콘센트 문장이며 제목에도 동일 이름을 포함한다.

## 발견 사항

### 1. [P1] 등록 상세 주소를 읽지 못하면 검증 조건 자체가 사라짐

위치: `backend/recommendations/services/automatic_content_review.py:160-163`, `228-240`.

| 등록 상세 | 본문 상세 | 등록 상세 파싱 결과 | 실제 판정 |
| --- | --- | --- | --- |
| `1~2층` | `3층` | `{}` | approve |
| `제101호` | `102호` | `{}` | approve |
| `본관지하1층` | `2층` | `{}` | approve |

`_address_units()`가 모르는 형식을 만나면 빈 사전을 반환한다. `None`이 들어 있는 경우만 검사 실패로 처리하므로, 등록 상세 정보가 빈 사전이 되면 비교 반복도 비어 승인된다. `층수: 미확인`은 보류하도록 테스트했지만 라벨 없는 범위·접두어 표기의 미해석은 보호하지 못한다.

등록 정보가 없는 경우와, 등록 정보가 있지만 해석하지 못한 경우를 구분해야 한다. 지원되지 않는 상세 표기를 상세 정보 없음으로 처리해서는 안 된다.

### 2. [P1] 다른 동·본관·별관을 버리고 같은 호수/층수로 판정

위치: `automatic_content_review.py:155-162`.

`A동 101호` 대 `B동 101호`, `101동 201호` 대 `102동 201호`, `본관 1층` 대 `별관 1층`이 모두 승인된다. 동·관 이름을 건너뛰는 장식어로 처리하고 결과에 저장하지 않기 때문이다.

같은 도로명·건물번호를 쓰는 단지에서도 다른 동/관은 다른 장소일 수 있다. 이를 버리지 말고 상세 주소 구성 요소로 보존·비교해야 한다. 현재 테스트는 층/호의 차이만 확인하며 동/관 충돌은 포함하지 않는다.

### 3. [P2] 상세 주소 확인 뒤 약식 주소를 반복하면 정상 근거를 보류

위치: `automatic_content_review.py:233-237`.

- 등록: `중앙대로 100 1층`.
- 본문: `부산 중구 중앙대로 100 1층 테스트커피 서면점에는 콘센트가 있어요. 주소: 부산 중구 중앙대로 100`.
- 첫 주소에서 1층 일치를 확인했지만 두 번째 주소의 상세 정보가 `{}`라 전체 보류한다. 약식 주소를 먼저 쓰고 완전한 주소를 뒤에 써도 보류한다.

실제 층수 충돌을 단 한 번이라도 보류하는 것과, 이미 확인된 주소의 약식 반복을 충돌로 처리하는 것은 다르다. `test_repeated_same_address_remains_approved`는 등록 주소에 층수가 없는 경우만 확인한다.

대조 입력으로 1층과 2층을 모두 명시하면 현재도 보류됨을 확인했다. 보완 시 이 충돌 차단은 유지하면서 약식 반복과 모순을 구분해야 한다.

### 4. [P2] 같은 층·호수가 본문에 있어도 표기/순서 때문에 미확인 처리

위치: `automatic_content_review.py:132-138`, `160-163`.

- 등록 `101호`, 본문 `제101호` → 보류.
- 등록 `1층`, 본문 주소 뒤 `0507-1234-5678 1층` → 보류.
- 등록 `1층`, 본문 `중앙대로 100 테스트커피 서면점 1층에는 콘센트가 있어요.` → 보류.

모두 본문에 동일 상세 정보가 있지만 파서가 먼저 만난 호수 접두어·전화번호·장소명에서 중단한다. 이는 본문에 정보가 아예 없는 경우와 다르다. 직접 장소에 귀속된 상세 정보와 다른 시설의 층수 설명을 구분하면서 동등 표기·필드 순서를 처리해야 한다.

### 5. [P1] `제2호점`은 다른 지점으로 판별하지 못함

위치: `automatic_content_review.py:282-289`.

등록 이름 `테스트커피 서면점`에 대해 제목·본문이 `테스트커피 서면점 제2호점`이어도 승인된다. 지점 한정어 정규식이 숫자로 시작하는 `2호점`만 처리하고, 공백 뒤의 `제2호점`을 놓친다. 기존 구분자 회귀 테스트에 서수 접두어 변형이 없다.

### 6. [P2] 방문 횟수를 다른 주소로 오인

위치: `automatic_content_review.py:166-175`.

정상 근거에 `추가로 2번 방문했어요.`를 붙이면 `추가로 2`가 추가 도로 주소로 추출되어 보류된다. 현재 수량 제외 목록은 `잔`, `명`, `개` 등을 다루지만 방문 횟수 단위 `번`은 다루지 않는다. 주소 후보를 단순히 단위 목록 몇 개로 제외하는 방식에는 정상 문장 누락이 남아 있다.

## 층·호수 정책에 대한 판단

본문 전체에 층·호수 정보가 없을 때 보류하는 동작은 직전 보완에서 의도한 보수적 조건이며, 이 사실만으로 구현 오류라고 단정하지 않는다. 같은 상세 주소가 확인되는 경우의 승인, 상세 정보가 전혀 없는 경우의 보류, 명시적 층수 충돌의 보류를 대조 입력으로 확인했다.

반면 **확인된 상세 주소 뒤의 축약 반복**, **본문에 존재하는 동등 정보의 파싱 실패**는 정상 근거를 과도하게 보류하는 구체적 사례다. 등록 상세 주소의 파싱 실패를 무조건 정보 없음으로 처리하는 반대 방향의 오통과도 함께 해결해야 한다.

현재 24건 표본의 기존 결과 유지나 테스트 48개 통과만으로 이런 보류가 운영에서 얼마나 자주 발생하는지 추정할 수 없다. 이번에는 운영 데이터 분포를 조회하지 않았다.
