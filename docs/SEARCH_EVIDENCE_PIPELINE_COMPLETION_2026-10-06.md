# 검색 근거 파이프라인 후속 작업 결과 (2026-10-06)

기준: 운영 Django 컨테이너와 DB의 읽기 전용 집계, 현재 작업 폴더의 코드 및 SQLite 테스트. 운영 검색 코드는 이번 작업 이후 배포하지 않았다. 아래 전후 비교에서 `예상`은 운영 개선 실측이 아니다. 원문 검색어, 장소명, Evidence 인용문, 사용자 식별자는 기록하지 않았다.

## 1. 검색 실패 원인별 실제 사례와 범위

부산·서울 중심 5km에서 조건 6종씩 총 12개 통제 검색을 실행했다. 각 시나리오에서 DB 원시 후보 30개, Kakao 원시 후보 45개를 읽었다. 이 결과는 의도 해석 정확도 평가가 아니라, 동일한 후보 경로의 게이트·최종 반환 관측이다.

| 조건 | 부산 hard gate / 최종 | 서울 hard gate / 최종 | 관측한 손실 |
| --- | ---: | ---: | --- |
| 카페 | 58 / 5 | 60 / 5 | 상위 K 제한 |
| 조용함 | 15 / 0 | 0 / 0 | 부산은 게이트 후 fallback 손실, 서울은 후보·근거 부족 |
| 콘센트 | 14 / 2 | 0 / 0 | 부산 일부 게이트 후 손실, 서울은 후보·근거 부족 |
| 조용함+콘센트 | 5 / 1 | 0 / 0 | 부산 게이트 후 손실 |
| 조용함+콘센트+노트북 | 4 / 1 | 0 / 0 | 부산 게이트 후 손실 |
| 혼자+장기체류 | 0 / 0 | 0 / 0 | 현 검색 범위의 확인 조합 부족 |

분류: A Evidence/조건 조합 부족은 서울 5개 조건 검색과 부산 `혼자+장기체류`에서 나타났다. B Retrieval은 확인 태그 중심 추가 수집이 원시 Evidence 장소를 놓칠 수 있는 코드 경로가 확인되어 보강했다. C Identity/Evidence join은 현재 Kakao 후보 90개 중 보수적 내부 매칭 22개라는 실측이 있다. D 승격 병목은 아래 3절의 PlaceTag 격차다. E Ranking 가중치 역전 사례는 확인되지 않았다. 대신 부산의 엄격 조건 4개에서 게이트 통과 후보가 최종 단계에서 줄어드는 fallback 문제가 확인됐다. F Intent 오류 비율은 이 통제 검색으로 측정할 수 없다.

후보별 식별 상태·증거 수·게이트 사유·점수·순위를 원문 없이 남기는 opt-in trace를 구현했다. 위 운영 검색은 배포 전 코드이므로 새 trace가 아닌 단계별 통제 관측이다.

## 2. IDENTITY_MISMATCH 원인 분포

최근 14일 84,000 수집 작업 중 `IDENTITY_MISMATCH`는 55,457건(66.0%). 각 작업에 저장된 검색 결과 중 기존 점수가 가장 높은 한 건을 기존 분류기로 재분류한 결과다.

| 휴리스틱 범주 | 건수 | mismatch 중 비율 |
| --- | ---: | ---: |
| 잘못된 검색 결과 | 24,515 | 44.2% |
| 지역 불일치 | 11,768 | 21.2% |
| 이름 불일치 | 7,887 | 14.2% |
| 지점명 불일치 | 5,111 | 9.2% |
| 본문에 부수적으로 언급 | 4,233 | 7.6% |
| 기존 점수 임계치 미달 | 1,184 | 2.1% |
| 식별 정보 부족 | 759 | 1.4% |

이는 저장된 제목·요약을 이용한 기계 분류이며 사람 판정의 실제 원인 비율은 아니다. 주소 표기, 도로명/지번, 좌표, 상호 변경, 폐업·이전, 동명이점은 현 저장 정보만으로 신뢰성 있게 분리할 수 없다. 단순 fuzzy 병합은 도입하지 않았다. 진단 명령의 기본 출력에서도 원문·주소·URL을 제거했다. 기존 저장 정보를 읽는 분석과 달리 이 명령 자체는 외부 재검색을 하므로 이번에는 실행하지 않았다.

## 3. Evidence에서 PlaceTag로 가는 병목

운영 웹 집계 PlaceTag 34,781건 중 `candidate` 1,103, `needs_verification` 33,674, `confirmed` 0. Candidate 조합 1,103개 중 서로 다른 게시자/인용문에 해당하는 양성 근거가 2개 이상인 조합은 대략 888개, 3개 이상은 265개다. 서로 다른 2개 출처 유형과 평균 신뢰도 75 이상까지 만족한 것은 7개였다. 이 7개는 충돌·신선도를 모두 반영한 최종 승인 가능 수가 아니다.

웹 출처의 게시자와 정규화한 인용문을 함께 보아 복제·재가공된 근거의 독립성 중복 계산을 줄였다. 3개 이상 독립 양성, 평균 신뢰도 75 이상, 신선도 70 이상, 2개 출처 유형, 반대 근거 없음 조건으로 읽기 전용 검토 우선순위 명령을 만들었다. 자동으로 웹 근거를 확인 태그로 승격하지 않는다. 장소 일치와 충돌은 관리자 판단이 필요하다.

## 4. 부산·서울 조건 조합 coverage

도시 전체 카페의 유효 양성 원시 Evidence를 현재 게이트의 만료·검토·충돌·의미 정책에 가깝게 다시 집계했다. 원시 후보 수는 실제 검색 결과 수가 아니다.

| 지역·조건 | 원시 Evidence 조합 후보 | 확인 PlaceTag 조합 |
| --- | ---: | ---: |
| 부산 조용함+콘센트 | 32 | 4 |
| 부산 조용함+콘센트+노트북 | 20 | 0 |
| 서울 조용함+콘센트 | 3 | 0 |
| 서울 조용함+콘센트+노트북 | 3 | 0 |

앞선 단순 긍정 Evidence 집계의 부산 첫 조합 33과 이번 32의 차이는 충돌·의미 정책 적용 범위 때문이다. 가까운 5km 검색에서 서울의 해당 조합이 0인 것과 도시 전체의 3은 서로 다른 범위다.

## 5. 수집 우선순위 개선

부족 검색 수요의 키를 `위치×업종×필수 태그 조합`으로 고정했다. 현재 반환 수가 달라도 같은 결핍 신호가 누적된다. 이미 확인된 조합은 결핍 보정에서 제외하고, 우선순위 계산에서 유효 양성 근거와 확인 태그를 읽어 중복 조사를 줄였다. 실제 배치 큐 재배치 전후의 신규 확인 조합 증가량은 아직 운영 실측이 없다.

## 6. 외부 후보의 내부 Place identity 연결

90개 Kakao 후보(부산·서울 각 45개)를 보수적으로 대조했다. Kakao ID와 장소 정체성 일치 7, 같은 전체 이름 및 주소/30m 이내 일치 15, 모호한 중복 5, 불일치/부족 63이다. 매칭률은 22/90(24.4%)이며 사람이 레이블한 false-match 정밀도는 아직 없다.

별도 identity lookup을 구현했다. Kakao ID만 같아도 전체 이름·주소 또는 좌표를 확인하고, 웹 후보는 좌표가 없다면 전체 이름·주소 일치를 요구한다. 모호하면 미확인으로 둔다. 내부 Place가 명시적으로 일치한 후보에만 기존 태그·Evidence를 붙인다. 이 기능을 켰을 때 내부 ID가 없는 외부 후보가 일반 중복 제거 과정에서 내부 ID를 물려받지 않도록 막았다. 기능은 기본 꺼짐이다.

## 7. Ranking 수정 필요 여부

운영 AI reranker가 꺼져 있어 `_hybrid_score` 가중치 변경 근거가 없다. 가중치는 바꾸지 않았다. 부산 `조용함`은 gate 15개 중 최종 0개였고, 비활성 reranker 이후 fallback에서 확인 후보가 사라지는 경로를 수정했다. 같은 운영 후보에 새 fallback 규칙을 적용한 계산은 `조용함` 15개 중 조건·결과 정책 확인 14개, 두 조건 5/5, 세 조건 4/4다. Top 5 한도로 각각 최대 5, 5, 4개가 될 수 있다는 **배포 전 예상**이며 실제 운영 검색 후 결과가 아니다.

## 8. 실시간 AI Web Search 파일럿

확인 후보 3개 이상이면 생략, 2개면 명시적 확장에만 실행, 0~1개면 1쿼리·최대 3후보를 허용하는 opt-in 경로를 구현했다. 웹 후보는 내부 identity와 기존 확인 Evidence를 통과해야 기본 확인 결과에 들어간다. 실패 시 원래 DB/Kakao 결과를 보존한다. 10분 인메모리 캐시 키의 검색어 공백·대소문자를 정규화했다.

운영은 `AI_PROVIDER=rule`, AI Web Search 비활성, OpenAI/GMS 키 미설정 상태여서 실제 AI 제공자 파일럿은 실행할 수 없었다. 따라서 발동률·추가 지연 p50/p95·실제 Top-K 순증·무개선 비율은 아직 없다. 현재 로그는 웹 유래 후보의 확인 Top 5 포함을 기록하지만 이를 순증 효과로 해석하면 안 된다.

## 9. 검색 품질 전후

현재 운영 전 기준은 1절의 12개 통제 검색이다. 로컬 변경 후 Django 추천 테스트 1,004개 통과, 19개 건너뜀. 원시 Evidence 장소를 가까운 후보 창 밖에서도 추가 검색하는 회귀 테스트와 잘못된 외부 ID 병합 방지 테스트를 포함한다. 부산 fallback 수치와 서울 조합 결핍은 개선 가능 범위의 계산이며, 운영 배포 후 동일 12개 검색·후보별 trace·지연을 다시 측정해야 실제 전후가 된다.

후보/게이트/최종 단계 수, identity 성공/실패, Evidence 연결, 웹 후보, 검색 단계 지연을 민감 원문 없이 기록하는 opt-in 구조화 로그를 추가했다. 운영 대시보드나 CloudWatch 일일 집계는 아직 연결되지 않았다.

## 10. 남은 P0/P1/P2

- **P0:** 공유 작업 폴더의 다른 미완료 변경과 검색 파이프라인 변경을 분리해 리뷰·배포한 뒤 기능 플래그를 제한적으로 켠다. 동일 12개 검색의 후보별 trace, gate, 실제 Top 5, p50/p95를 전후 비교하고 회귀 시 플래그를 끈다. 운영 AI 공급자 없이도 fallback·identity·원시 Evidence retrieval 효과부터 검증한다.
- **P1:** 독립 근거 우선 검토 queue의 장소 정체성·반대 근거를 관리자 표본으로 평가하고 승격 처리 경로를 연결한다. 주소/지점/이전 원인 레이블 표본과 identity false-match 평가를 만든다. 검색 결핍 신호를 실제 배치 큐에 반영하고 확인 조합 순증으로 측정한다. 제공자 키·비용 한도·권한이 준비되면 소규모 실시간 AI Web Search를 켜고 발동률·지연·순증을 측정한다.
- **P2:** 실제 확인 후보의 순위 역전이 기록될 때만 점수/티어를 조정한다. Django p95와 서비스 격리 이득이 실측되기 전 FastAPI 전환은 추진하지 않는다. 단계별 로그의 보존량을 보고 대시보드 스택을 결정한다.
