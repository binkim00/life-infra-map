## 2. 사용자 요구와 작업 범위

- 앱 우선. 앱 완료 전 웹으로 범위를 넓히지 않는다.
- 일반 검색 = 네이버맵·카카오맵처럼 장소명/브랜드/지점/지역·업종 검색. AI 불필요.
- 상호만 입력하면 주변 관련 지점, 명시한 지역이 있으면 그 지역, 지도 재검색은 보고 있는 지도 영역을 기준으로 한다. 가까움만으로 관련 없는 장소를 우선하면 안 된다.
- 특정 카페/지명을 추가하는 하드코딩 금지. 사용자는 문제 카페 이름 제공도 거절했다. 범용 규칙과 다양한 지역·상호 테스트로 해결해야 한다.
- 상황 검색 = 충분한 정보면 바로 결과, 부족하거나 후보가 불확실하면 필요한 질문으로 후보를 좁힘. 후속 답변에서 기존 지역·조건 유지.
- 이름 클릭으로 상세 진입, 사진/영업정보 등 쓸 만한 상세, 찾기 쉬운 장소 제보가 필요하다. 없는 사실을 만들면 안 된다.
- 물리 휴대폰 사용하지 않는다. Expo 소스 업로드 → Preview APK → Android 에뮬레이터 검증 요청.
- 사용자 불만: 이전에 일부 테스트만으로 정상이라고 보고해 실제 사용에서 많은 실패가 발생. **빌드/테스트 통과를 전체 기능 정상으로 보고하지 말 것.**
- 서브에이전트 금지, 불필요한 반복 탐색/전체 테스트/잦은 빌드 상태 조회 금지. 토큰 절약 중요.
- 마지막 요청은 인수인계 문서 작성이다. 직전 작업은 검증만 수행했다. 이 문서는 새 수정/커밋/운영 배포에 대한 추가 승인 자체가 아니다. 새 채팅의 사용자 요청 범위대로 진행한다.

## 5. 재현된 실패와 원인 — 다시 처음부터 발견할 필요 없음

### P1 일반 검색 후보 수집/지도 재검색

- 로컬 수정본+실제 Kakao, 기준 `lat=35.1577,lng=129.0591`:
  - `부산역` → 0건.
  - `서울역` → 창원의 서울역떡집 1건, 약 44.6km.
  - 원인: 좌표 전달 시 Kakao **거리순 첫 15개**만 수집. 원본 후보에 해당 역이 없음. 이후 필터/정렬로 복구 불가능. 관련도 기반 후보 수집도 필요하며, 거리순만 강화하면 또 실패한다.
  - `스타벅스 카페`, radius 1500: auto는 스타벅스, center_mode=map은 앤더스/쉬즈티스토리 등 일반 카페. map 모드에서 category_query만 사용해 상호 소실.
  - `부산 전포 카페` → anchor_resolved=false, 서면역 근처 카페. 복합 지역명 처리 실패.
- category substring 추론, 지역+브랜드 좌표/라벨 일치도 추가 검증 필요.
