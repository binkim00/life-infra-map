# content-v9 최종 diff 및 회귀 테스트 재검토 — 2026-10-22

후속 상태: 아래 6종은 content-v10 로컬 수정과 회귀 테스트에 반영했다. 재현 입력 28/28 및 관련 테스트 66개가 기대대로 통과했다. 수정·검증 내역은 `docs/ADDRESS_MATCHING_LOCAL_FIX_2026-10-22.md`의 content-v10 절에 있다. 아래 내용은 수정 전 검토 이력이며 운영 반영을 뜻하지 않는다.

## 결과

추가 보완 6종이 남아 있다. 관련 테스트 60개는 모두 통과했지만, 새 가상 입력 28개에서 예상과 다른 승인 11개, 예상과 다른 보류 7개를 재현했다. 나머지 10개 대조 입력은 예상대로다. 이 수치는 운영 데이터의 오류 건수나 오류율이 아니다.

층·호수 완전 부재 보류, 일반적인 조사 뒤 상세 정보, 전체를 확인한 범위의 부분 반복, `1층~2층/1~2층` 동등 표기는 대조 입력에서 정상이다. 하지만 미해석 범위의 뒷부분과 구두점이 있는 이름 뒤의 상세 정보를 놓쳐, 이를 정상 약식 반복과 구분하지 못하는 경로가 남아 있다.

검토는 로컬 `backend/recommendations/services/automatic_content_review.py` 및 `test_address_matching.py`에 한정했다. 구현·회귀 테스트 소스는 수정하지 않았다. 운영 접속·배포·설정/데이터 변경·보류 해제도 하지 않았다.

## 검증 근거

- 코드·테스트 SHA-256이 직전 content-v9 완료 기록과 동일하며 검토 종료 시에도 유지됐다. 정확한 해시, 재현 입력, 최종 판정, 주소별 추출 상세 정보: `runtime/address-matching-v9-review-20261022/results.json`.
- `test_address_matching`, `test_automatic_content_review`, `test_codex_content_review` 총 60개 재실행 통과. Django 시스템 검사도 통과했다. 실행 로그: `runtime/address-matching-v8-review-20261022/v9-review-tests.txt`.
- 기존 저장·복구 테스트는 `config.test_settings`의 SQLite 메모리 DB에서 실행했다. 새 가상 입력은 DB cursor와 네트워크 socket을 차단하고 미저장 객체의 순수 판정 함수만 호출했다.
- 대상 소스 `git diff --check` 통과. 원격 CI·다른 컴포넌트 전체 빌드는 실행하지 않았다.
- 아래 사례는 원시 주소 비교만이 아니라 `assess_content()`의 최종 승인/보류까지 재현했다. 공통 도로 주소는 `부산 중구 중앙대로 100`, 장소 이름은 `테스트커피 서면점`이며 별도 표시가 없으면 제목에 정확한 이름과 본문에 해당 장소의 직접 콘센트 문장이 있다.

## 발견 사항

### 1. [P1] 해석하지 못한 범위·열거의 뒷부분을 버리고 첫 값만 확인

위치: `automatic_content_review.py:202-223`, `250-273`.

| 등록 상세 | 본문 상세 | 실제 판정 |
| --- | --- | --- |
| B1~B2 | B1 | approve |
| B1 | B1~B2 | approve |
| 101호 | 101호~103 | approve |
| 1층 | 1층 및 2층 | approve |

처음 해석한 값 뒤 `~B2`, `~103`, `및 2층`에서 중단한 뒤, 부분 파싱 결과를 유효 상세로 반환한다. 등록 범위 전체를 확인하지 않았거나 본문에 추가 범위가 있어도 첫 값의 일치만으로 승인한다. 지원되지 않는 범위/열거 연결은 미해석 상태로 남겨 보류하거나, 전체를 안전하게 읽어 비교해야 한다.

기존 범위 회귀 테스트는 양 끝 단위가 완전한 형태와 단순 부분 반복을 검사한다. 문장 중간 중단이 원래 전체 범위를 잘라내는 경우는 포함하지 않는다.

### 2. [P1] 일부 층·호수 표기를 건물번호로 인정

위치: `automatic_content_review.py:41-44`.

등록 주소 `중앙대로 100`에 대해 본문이 `중앙대로 100층입니다.`, `중앙대로 100층인 ...`, `중앙대로 100호실 ...`이면 승인한다. 층·호수 표시가 붙은 숫자를 도로의 건물번호 100으로 추출하고, 남은 `층입니다/층인/호실`은 상세 정보로도 읽지 않는다.

층·호수 뒤의 일부 조사만 열거한 주소 숫자 경계 검사 때문에 `100층에`는 막지만 `100층입니다`와 `100호실`은 통과한다. 주소 건물번호의 존재를 확인하지 못한 입력이므로 보류해야 한다.

### 3. [P1] 제목의 다른 동·건물 한정어를 비교하지 않음

위치: `automatic_content_review.py:409-416`.

- 등록 주소 A동 101호, 본문도 A동 101호인데 제목은 `테스트커피 서면점 B동 후기` → approve.
- 등록 주소 알파빌딩 1층, 본문도 알파빌딩 1층인데 제목은 `테스트커피 서면점 베타빌딩 후기` → approve.

주소 파서는 본문만 비교하고, 이름 접미어 검사는 알려진 관 이름·숫자 호점·분점만 차단한다. 본문과 제목의 건물 정체성 충돌이 검사 사이에서 빠진다. 본문 주소가 맞다는 이유로 제목의 다른 동/건물 한정어를 무시해서는 안 된다. 대조한 제목의 `별관`은 현재도 보류된다.

### 4. [P1] 이름의 구두점 처리 차이가 상세 정보의 과도한 보류와 오승인을 만듦

위치: `automatic_content_review.py:162-175`, `402-416`.

- 등록 1층, 본문 `주소 + 테스트커피·서면점은 1층에 있고 콘센트가 있어요.` → hold.
- 위 이름을 `'테스트커피 서면점'`으로 감싸도 동일하게 hold.
- 등록 2층, 완전한 2층 주소와 직접 콘센트 문장을 먼저 쓴 뒤 `주소: 같은 도로/번호 + 테스트커피·서면점은 1층에 있습니다.`를 덧붙임 → approve. 따옴표 표기도 동일하다.

이름 정체성 검사는 이름 내부 구두점을 허용하지만 주소 상세 연결은 공백만 허용하고, 앞의 따옴표도 구분자로 소비하지 않는다. 따라서 같은 이름의 정상 층수는 읽지 못하고, 이미 다른 주소를 확인한 경우에는 명시적 충돌을 정보 없는 약식 반복으로 취급한다. 두 검사에서 허용하는 동일 이름의 표기 기준을 맞춰야 한다.

### 5. [P2] 건물명 중간의 동·상가에서 일찍 끊어 정상 주소를 보류

위치: `automatic_content_review.py:61-64`, `224-256`.

등록 주소와 본문에 각각 동일한 `신동아빌딩 1층`, `강동타워 1층`, `중앙상가빌딩 1층`을 넣어도 모두 보류된다. 비탐욕 건물명 정규식이 `신동`, `강동`, `중앙상가`를 먼저 선택하고, 남은 글자가 허용 경계가 아니면 전체 건물명을 다시 읽지 않고 미해석으로 확정한다.

정확한 같은 건물 이름을 보존하되 단어 중간을 동/건물 접미어로 확정하지 않아야 한다. 기존 건물 회귀 입력은 이름 중간에 동·상가 등이 없는 `알파빌딩`, `알파타워`, `교육관` 등에 한정돼 있다.

### 6. [P2] 도로명 주소의 행정동을 건물 동으로 잘못 요구

위치: `automatic_content_review.py:224-230`, `342-360`.

- 등록 `부산 중구 중앙대로 100 (중앙동) 1층`, 본문 `부산 중구 중앙동 중앙대로 100 1층` → hold.
- 등록은 위와 같고 본문에서 괄호 속 중앙동만 생략해도 hold.
- 반대로 등록 주소에서 중앙동을 도로 앞에 쓰고 본문에서 괄호 속에 쓰면 approve.

괄호 속 행정동이 건물 동 구성 요소 `동: 중앙`으로 저장되어 필수 확인 조건이 된다. 동일 행정동의 위치 이동이나, 시·구·도로명·건물번호·층수가 그대로인 주소에서 선택적 행정동의 생략을 다른 건물 동의 부재와 혼동한다. 실제 A/B동 충돌 보류는 유지하면서 행정동과 건물 동을 구분해야 한다.

## 정상 유지와 한계

대조 입력 10개에서 층·호수 부재 보류, 일반적인 이름+조사 뒤 같은 층 승인, 완전히 확인된 범위의 부분 반복 승인, 미확인 부분 범위 및 범위 밖 값 보류, 양 끝 단위의 동등 표기 승인, 별관 제목 보류, 화장실 층수와 매장 층수 구분이 유지됐다.

운영 분포는 조회하지 않았고 모든 자연어 주소 표현을 검증한 것도 아니다. 새 실패 입력은 회귀 테스트 소스에 추가하지 않고 재현 JSON에만 저장했다.
