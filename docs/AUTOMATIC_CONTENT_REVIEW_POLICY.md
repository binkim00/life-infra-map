# 수집 근거 자동 내용 승인 정책

정책 버전: `content-v3-20260910`

## 목적

관리자가 모든 수집 건을 수동 승인하지 않아도, 장소와 문장이 타당한 근거는 자동으로 수용한다. **내용 승인과 현재 사실 확인은 다르다.** 오래됐거나 제목에 지점명이 생략됐다는 이유만으로 제외하지 않는다. 원문에 접속할 수 있는지를 매번 승인 조건으로 요구하지 않는다.

## 판정

- 장소 이름이 제목 또는 본문에서 일치하거나, 일부 상호와 정확한 도로명·번지가 맞으면 장소 연결을 인정한다. 기존 공급자의 장소 연결 검사도 함께 사용한다.
- 프랜차이즈·지점형이 아닌 장소는 제목이나 문장에 정확한 상호가 생략됐더라도 수집 단계의 장소 연결을 수용한다. 프랜차이즈·지점형은 정확한 전체 지점명이 문맥에 없으면 제한 승인한다.
- 저장 주소와 문장에 나온 도로명·번지가 다르면 이전·다른 지점 가능성이 있으므로 제한 승인한다.
- 여러 장소를 소개한 글은 해당 장소의 정확한 이름 주변 문장에서 태그의 긍정·부정 방향이 확인되면 승인하고, 연결할 수 없으면 제한 승인한다.
- 노트북 사용 금지, 혼밥 불가, 데이트하기 좋은 분위기가 아님처럼 저장 극성과 명시적으로 반대인 문장은 반려한다. 다른 도시·지역이 명시된 연결도 반려한다.
- 위 세 가지 연결 불확실성이나 명시적 반대가 아니면 사용자 위임의 완화 기준에 따라 내용 승인한다. 만료 기간은 승인 여부와 분리한다.
- 같은 장소·태그·극성·정규화 URL·인용문이 중복이면 대표 원본을 보존하고 후속 중복의 검토 상태만 반려로 둔다. 서로 다른 태그나 서로 다른 후기는 중복으로 합치지 않는다.

## 승인 이후 사용

- 자동 검토는 `EvidenceReview`에 정책 버전, 사유, 인용문 해시, 실행 식별자를 기록한다. 검토자 계정을 사칭하지 않고 `reviewer`는 비워 둔다.
- 자동 승인 자체로 관리자 현장 확인 근거(`admin_review`)나 확인 시각을 만들지 않는다. 원본 인용문·관측일·만료일은 바꾸지 않는다.
- 현재 유효한 자료는 기존 웹 근거 집계 정책으로 검색에 반영한다. 자동 승인 자체가 곧 `is_verified=True`라는 뜻은 아니다.
- 만료된 승인 자료는 `과거 자료·현재 미확인`의 별도 보조 정보다. 현재 검증/후보/경고 태그 및 필수 조건 충족 목록에 섞지 않는다. 현재 자료 또는 상충하는 과거 부정 자료가 있으면 과거 긍정 근거로 덮어쓰지 않는다.
- 명시적인 검토 대기·반려·재조사 자료는 현재 근거 집계와 필수 조건 검사에서 제외한다.
- `제한 승인(approved_limited)`은 자료 자체를 버리지는 않되 장소·지점·조건 연결을 검색에 쓰기에는 불확실한 상태다. 관리자 보관함에서는 별도로 조회할 수 있지만 현재 근거 집계, 검색 필수 조건, 검증 근거 보유율에는 포함하지 않는다.
- 관리자의 기존 승인·반려·대기 결정은 자동 작업이 덮어쓰지 않는다. 자동 검토 자료의 문장이 변경되면 다시 판정하며, 같은 내용의 재수집은 이력을 중복 추가하지 않는다.

## 적용 경로

- `save_place_candidate_evidence`: 네이버/웹 수집, 공개 페이지 수집, Codex 웹 근거 저장, 재검증 등의 공통 저장 경로.
- `reextract_web_evidence_tags`: 재추출로 생성된 자료도 동일 정책을 적용한다.
- API와 수집 worker/scheduler에 같은 백엔드 이미지를 적용한다. 외부 수집 호출량, 스케줄, API 키 설정을 바꾸지는 않는다.

## 기존 데이터 일괄 처리

`apply_automatic_content_review`는 읽기 전용 사전 분류에서 생성한 ID·정책 해시·원문 해시·수정 시각에 고정된 manifest를 사용한다. 운영 적용 전 순서는 다음과 같다.

1. 전체 후보 사전 분류 및 기존 수동검토 오인용 사례와 대조.
2. 코드 테스트와 배포 상태 확인.
3. 일부 대상 시험 적용 후 전체 롤백 확인.
4. 새 전용 경로에 원본·검토·관리자 근거·검색 태그 백업을 만든 뒤 200건씩 적용.
5. 청크별 결과 기록 및 최종 API·DB·원본 보존 대조.

이미 검토된 행은 보존하고, 사전 조회 이후 원문/식별 정보가 바뀐 행은 건너뛴다. 부분 실패 시 완료 영수증과 검토 이력을 확인한 뒤 남은 대상을 처리한다. 백업 파일이나 manifest를 덮어쓰지 않는다. 코드 롤백과 데이터 롤백은 별개이며 DB 전체 초기화나 광범위 삭제를 사용하지 않는다.

### 보류 3차 판정

- 제한 승인10,139건을 다시 분류한다. 주소 불일치, 프랜차이즈·지점명 미확인, 다중 장소 문맥 미해결만 제한 승인으로 유지한다.
- 비프랜차이즈이거나 정확한 전체 장소명이 저장 제목·인용문에 있는 장소 연결은 승인한다.
- 다중 장소 글은 장소명 앞뒤160자의 문맥에서 같은 태그 극성이 확인되면 승인한다.
- 그 밖의 이전 제한 사유는 승인하되, 저장 문장에 명시적 금지·불가·반대 표현이 있으면 반려한다.
- 동네명 불일치만으로 제한하거나 반려하지 않는다. 행정동·생활권 표기가 달라도 주소와 장소가 맞는 실제 사례가 있기 때문이다.

## 한계

자동 내용 검사는 규칙 기반이며 모든 원문을 사람이 정독하거나 현장을 확인한 것이 아니다. 제목·주소를 생략한 후기, 지점 이전, 문장이 잘린 검색 결과는 추가 검토가 필요할 수 있다. 과거 자료 승인 수가 늘어도 현재 검증 근거 보유율 게이트를 통과했다는 뜻은 아니다.
