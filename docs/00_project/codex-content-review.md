# Codex 2차 근거 내용 검토

## 상태

2026-09-29 사용자 승인 후 운영에 배포하고 타이머를 활성화했다. 첫 서비스 실행에서 3건을 검토해 자동 승인은 0건이었다. 별도 미리보기 표본에서 원문과 장소·주소·직접 태그 표현을 확인한 1건(ID 395564)만 수동 선택 적용했다. 영속 백업, DB 승인 상태, 검색 활성, 되돌리기 미리보기를 확인했다. 실패 알림 서비스 설정은 확인했으나 실제 메일 전달은 시험하지 않았다. 기존 Codex 웹 근거 수집 타이머는 별도로 운영 중이다.

## 판정 경계

1. Django가 자동 내용 규칙으로 보류했고 사람이 다시 판정하지 않은 웹 근거만 최대 5건씩 고른다.
   최근 7일 동안 이미 2차 검토 대상으로 내보낸 근거는 건너뛰고 다음 대기 건을 선택한다. 실패·보류 건은 7일 뒤 다시 후보가 된다.
2. 공개 원문을 서버가 직접 읽어 저장 문장과 가까운 장소 문맥만 Codex CLI에 전달한다. 원문 접근 불가, 인용 불일치, 장소명과 멀리 떨어진 문장은 모델 호출 전에 제외한다.
3. Codex는 `approve` 또는 `hold`와 원문 속 20~600자 연속 인용문을 구조화해서 반환한다. 공급자 검색 API나 별도 유료 LLM API를 호출하지 않는다.
4. 승인 후보도 서버가 원문을 다시 가져와 같은 URL, 인용문, 정확한 장소명, 주소, 저장 문장과의 겹침, 긍정 주장, 승인된 반대 근거, 원본 수정 여부를 검사한다. 조건 하나라도 실패하면 보류한다.
   `카공`처럼 공부 가능성만 말하는 문장은 `노트북작업`의 직접 증거가 아니므로 명시적 노트북·랩탑 표현이 없으면 보류한다.
5. 승인 시 원본 관측일·만료일은 바꾸지 않는다. 자동 판단은 사람의 현장 확인으로 표시하지 않는다. 만료된 근거가 내용상 승인돼도 최신 검색의 활성 근거가 되지 않는다.

## 표본 평가

- 기존 승인 20건 중 원문 선별 8건: Codex 승인 후보 4건, 마지막 원문 검사 통과 4건. 네 문장을 직접 확인했다.
- 개별 보류 20건 중 원문 선별 7건: Codex 승인 후보 1건, 마지막 원문 검사 통과 1건. 이 건은 원문에 같은 장소명·주소와 직접 혼밥 표현이 있었지만, 과거 보류 판정과 충돌하므로 작은 표본으로 전체 정확도를 단정하지 않는다.
- 처음에는 Codex 웹 검색으로 네이버 원문을 읽지 못해 6건 모두 보류됐다. 서버 원문 검사기가 같은 원문을 읽는 것을 확인하고, 검색 대신 검증된 발췌를 전달하는 방식으로 바꿨다.

## 운영 적용 전 확인

- 운영 DB 백업과 복원 가능 상태, 루트 디스크 여유, Django migration 적용 상태를 확인한다.
- `/home/ubuntu/life-infra-map/runtime/codex-evidence/content-review`를 `ubuntu` 소유의 0700 디렉터리로 **Django Compose 재시작 전에** 만든다. Compose가 이 경로를 컨테이너 `/codex-content-review`에 연결한다. 백업이 컨테이너 밖에 먼저 저장되지 않으면 자동 적용을 켜지 않는다.
- 새 코드 배포 후 `CODEX_CONTENT_REVIEW_APPLY=0`으로 1회 미반영 실행해 결과 JSON과 관리자 근거 화면의 대상 상태를 대조한다.
- 검증 후에만 `life-infra-map-codex-content-review.service`와 `.timer`, 실패 알림 서비스를 설치·활성화한다. 서비스는 하루 최대 5건, 04:30 Asia/Seoul 실행을 설정한다. 기존 연구 작업과 같은 잠금 파일을 사용하며 실패 시 기존 SNS 주제로 별도 알림을 보낸다.
  하루 5건 제한은 실행 횟수가 늘어나도 유지되도록 영속 실행 표식으로 계산한다. 실패한 적용도 보수적으로 그날 사용 건수에 포함한다.
- 첫 적용 후 backup 파일 존재, 승인 건수, 상태 읽기 결과, 검색 활성화 여부, 다음 수집에서 중복 생성 여부를 직접 확인한다. 실패·오승인에 대한 알림 설정은 운영 활성화 전에 추가 확인한다.

## 되돌리기

각 적용 배치의 `backup-*.json`은 영속 폴더에 선행 저장된다. 사람이 후속 판정하거나 원문이 바뀐 건은 자동 되돌리기에서 중단한다. 먼저 `python manage.py rollback_codex_content_review <backup>`으로 대상과 상태를 미리 보고, 그다음 필요할 때 `--apply`를 붙인다. 원본 근거 날짜를 바꾸지 않고 검토 상태를 복원한 뒤 집계 태그를 다시 계산한다.

## 남은 검증

운영 배포·첫 타이머 실행·실제 DB 승인 읽기·장기 정확도 표본·실패 알림을 검증하지 않았다. 서버 원문 접근 정책이나 페이지 구조가 바뀌면 자동 승인율이 떨어질 수 있다.
