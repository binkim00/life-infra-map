# 통합 서비스 방향 정리

## 1. 정리 목적

본 문서는 기존 프로젝트 기획과 팀원이 제안한 자연어 검색/후기 기반 태그화 방향의 차이를 정리하고, 현재 프로젝트에서 반영할 통합 방향을 정의한다.

팀원 제안은 기존 기획을 대체하는 것이 아니라, 기존의 “상황 기반 생활 장소 추천 지도 서비스”에 자연어 태그 검색과 후기 기반 추정 태그 요소를 보강하는 확장안으로 본다.

---

## 2. 최종 서비스 방향

본 서비스는 기존 지도 서비스처럼 장소명을 직접 검색하는 서비스가 아니다.

여러 출처에서 확보한 장소 데이터를 카테고리와 태그로 분류하고, 사용자의 자연어 입력 또는 빠른 선택 조건을 카테고리/태그 조건으로 변환하여 상황에 맞는 장소를 추천한다.

추천 결과는 지도와 목록에서 확인할 수 있도록 제공한다.

### 한 줄 정의

> 사용자의 위치와 상황을 기반으로 지금 필요한 생활 장소를 추천하고, 추천 결과를 지도에서 확인할 수 있는 상황 기반 장소 추천 서비스입니다.

---

## 3. 기존 기획에서 유지할 부분

기존 방향의 중심은 실제 확보 가능한 장소 데이터 기반 추천이다.

- 공공데이터, CSV, API, 팀 시드 데이터를 중심으로 장소 데이터를 확보한다.
- 흡연구역, 공중화장실, 공원, 쉼터, 공공와이파이 등 생활 인프라 데이터를 우선 검토한다.
- 장소별 카테고리와 기본 태그를 저장한다.
- 추천은 카테고리, 태그, 거리, 최신성, 신뢰도 등을 기준으로 규칙 기반 점수를 계산한다.
- 추천 결과는 목록과 지도 마커로 표시한다.
- 장소 상세에는 태그, 출처, 최신 확인일, 신뢰도 정보를 표시한다.

---

## 4. 팀원 제안에서 흡수할 부분

팀원 제안은 기존 기획을 바꾸는 것이 아니라 다음 기능을 보강하는 방향으로 반영한다.

- 자연어 검색창
- 빠른 지도 탭
- 블로그 검색 결과 기반 추가 태그 후보
- 태그 매칭 기반 추천 흐름
- 후기 기반 추정 태그 표시
- 태그 근거 링크 제공
- AI/GMS를 자연어 입력 → 추천 조건 변환에 활용

---

## 5. 데이터 활용 방향

### 5.1 기본 장소 데이터

초기 구현에서는 실제 확보 가능한 데이터를 우선 사용한다.

- 공공데이터 기반 장소
- 정제 가능한 CSV/JSON 데이터
- 팀이 직접 확인한 소량의 시드 데이터
- 지도 API를 통한 실시간 후보 장소

지도 API 검색 결과는 모든 데이터를 DB에 대량 저장하는 용도가 아니라, 장소 후보 조회와 부족한 추천 후보 보완에 활용한다.

### 5.2 블로그 검색 결과 기반 태그 후보

블로그 검색 결과는 장소의 추가 태그를 추정하는 보조 자료로 활용한다.

활용 대상은 다음과 같다.

- 제목
- 요약
- 작성일
- URL

본문 전체 분석을 핵심 기능으로 두지 않는다.

블로그 검색 결과에서 특정 표현이 반복되면 추가 태그 후보를 생성할 수 있다.

예시:

- “조용하다”, “한적하다”, “차분하다” → 조용함 후보
- “시끄럽다”, “붐빈다”, “웨이팅” → 조용함 점수 감소
- “저렴하다”, “양이 많다”, “부담 없다” → 가성비 후보
- “비싸다”, “가격대가 있다” → 가성비 점수 감소

이 태그는 확정 정보가 아니라 “후기 기반 추정 태그”로 저장한다.

---

## 6. 태그 관리 방향

태그는 출처와 상태를 구분해서 관리한다.

| 태그 종류 | 설명 |
|---|---|
| 기본 태그 | 카테고리 기반으로 부여한 태그 |
| 규칙 기반 태그 후보 | 키워드, 유의어, 부정어 점수로 생성한 태그 |
| 후기 기반 추정 태그 | 블로그 검색 결과를 바탕으로 추정한 태그 |
| 검증 태그 | 팀, 관리자, 사용자 검증을 거친 태그 |

PlaceTag는 단순히 장소와 태그를 연결하는 테이블이 아니라, 태그의 출처, 상태, 신뢰도, 검증 여부, 근거 정보를 관리하는 구조로 설계한다.

---

## 7. AI/GMS 사용 범위

AI/GMS는 실제 장소 정보를 임의로 생성하지 않는다.

AI/GMS는 사용자의 자연어 입력을 추천 조건으로 변환하는 역할에 집중한다.

예시:

```json
{
  "userInput": "주변에 조용히 앉아서 쉴 만한 카페",
  "placeTypes": ["카페"],
  "preferredTags": ["조용함", "휴식", "실내", "오래머무름"]
}
```

대량 장소 태깅은 AI/GMS보다 서버 내부 규칙 기반 로직을 우선한다.

---

## 8. 추천 점수 계산 방향

초기 추천은 복잡한 머신러닝이 아니라 규칙 기반 추천으로 구현한다.

```text
추천 점수 =
카테고리 일치 점수
+ 태그 일치 점수
+ 거리 점수
+ 최신성 점수
+ 신뢰도 점수
- 오류 제보 감점
```

태그 상태에 따라 반영 강도를 다르게 둔다.

- 검증 태그: 강하게 반영
- 후보 태그: 약하게 반영
- 확인 필요 태그: 안내 또는 감점
- 반려 태그: 추천 제외 또는 감점

---

## 9. 화면 구성 방향

첫 화면은 두 가지 진입 방식을 함께 고려한다.

### 9.1 자연어 검색 탭

사용자는 문장 형태로 원하는 상황을 입력한다.

예시:

- 조용한 카페
- 잠깐 쉬기 좋은 곳
- 흡연구역 근처 카페
- 가성비 좋은 밥집
- 산책하기 좋은 곳

### 9.2 빠른 지도 탭

사용자는 자주 쓰는 카테고리를 빠르게 선택한다.

예시:

- 흡연구역
- 공중화장실
- 카페
- 식당
- 공원
- 관광지

- 카테고리 필터
- 태그 기반 필터
- 외부 데이터 기반 장소 제공

- 빠른 지도 탭

## 11. 최종 결론

팀원 제안은 기존 기획을 그대로 대체하는 방향이 아니다.

현재 프로젝트는 기존의 “상황 기반 생활 장소 추천 지도 서비스”를 유지한다.

다만 자연어 검색, 빠른 지도 탭, 블로그 검색 결과 기반 추정 태그, 태그 근거 링크를 보강 기능으로 흡수한다.

따라서 최종 방향은 다음과 같다.

```text
공공데이터/시드 데이터로 기본 장소 확보
→ 기본 카테고리와 태그 부여
→ 블로그 검색 결과로 추가 태그 후보 생성
→ 자연어 입력을 태그 조건으로 변환
→ DB에서 규칙 기반 추천 점수 계산
→ 추천 결과를 지도와 목록에 표시
```
