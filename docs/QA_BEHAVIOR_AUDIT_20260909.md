**현재 일반 검색은 사용자 요구를 충족하지 않는다. 전체 기능 정상 또는 배포 품질 통과로 판정하지 않는다.**

이번 작업은 검사이며 서비스 코드 수정·서버 배포는 하지 않았다.

일반 검색 10건은 약 87~408ms였으나 DB 단독 희망공원 검색은 약 4,063ms였다. 표본 측정이며 서비스 전체 p95가 아니다.

### 원인 확인

1. `backend/recommendations/views.py`는 map 모드에도 좌표 없는 전국 관련도 검색을 합친다. 합친 Kakao 결과에 최종 반경 제한이 없어 먼 결과가 다시 들어온다.
2. 네이버 수집은 DB/Kakao 전체 결과가 모두 0일 때만 실행한다. 전국에 다른 지점이 있으면 부산 지점 보강 자체가 실행되지 않는다.
3. 일반 상호명 `source=all` 경로는 공공 업종 조건에 해당하지 않으면 `basic_db_skipped=True`로 DB를 건너뛴다. 사용자 요구인 DB 고유 장소 보강을 보장할 수 없다.
4. DB 단독 `희망공원` 검색에서는 희망공원뿐 아니라 보람공원·신호공원 등 30곳이 반환됐다. 이름 검색을 업종 검색으로 넓히는 문제도 존재한다. 같은 통합 검색에서는 DB 0/Kakao 15였다.
5. 네이버 후보 생성에서는 로컬 응답 좌표를 보존하지 않고, 최종 웹 후보 정규화도 lat/lng를 None으로 고정한다. 주소·링크가 있는 결과도 지도 위치를 제공하지 못한다.
6. 일반 검색은 전체 후보 경계로 지도 범위를 맞춘다. 잘못 수집한 전국 후보 때문에 부산 검색 화면이 전국 단위로 축소된다. 실기기 부산 중심 그라츠 검색에서 전주 첫 결과와 지도 축척 32km를 확인했다.

## 실제 재실행한 테스트

- Spring: `gradlew.bat test --rerun-tasks --no-daemon`, 119개 통과, 실패/오류/skip 0. H2 메모리 DB 사용.
- Django: 일반 검색 계약, 모바일 관리자/제보, 대화 세션, 대화 조건 누적의 48개 통과. 별도 SQLite 메모리 DB, 외부 비밀키 공백 처리, 운영 DB 미접속.
