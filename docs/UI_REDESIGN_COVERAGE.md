# LifeMap 모바일 UI 개편 커버리지

작성일: 2026-09-15

## 목적

이 문서는 모바일 UI 시안을 실제 라우트와 API에 대조해, 디자인 개편 과정에서 화면이나 동작이 빠지지 않도록 하는 체크리스트다. 시안에서 합쳐 보이는 화면도 구현 단계에서는 기존 라우트와 권한 경계를 유지한다.

## 공통 디자인 원칙

- 일반 검색은 익숙한 지도 검색 구조를 사용하되 DB, Kakao, 웹 후보의 출처와 지도 표시 가능 여부를 구분한다.
- 상황 추천은 충족 조건, 확인 필요 조건, 근거 출처를 결과 카드에서 바로 확인할 수 있게 한다.
- 모든 원격 목록 화면은 로딩, 빈 상태, 오류, 재시도를 서로 다른 상태로 보여준다.
- 저장, 삭제, 승인, 반려, 제재, 신고 같은 변경 동작은 진행 중 상태와 성공/실패 결과를 제공한다.
- 관리자 화면은 원시 JSON 대신 처리할 일, 상태, 다음 동작을 우선 표시한다.
- 지도에는 현재 위치, 현재 지도에서 재검색, 핀 선택, 결과 카드 연동을 일관되게 제공한다.

## 현재 계약에서 발견된 연결 공백

- `boardsApi.inquiry(id)` 상세 조회는 `/inquiries/[id]` 전용 화면과 연결했다.
- `aiWebSearch`, `searchSafety`, `interactions`, `saveSearchLog`는 별도 페이지가 아니라 검색·추천 흐름의 내부 동작이다. 화면 개편 뒤에도 검색 실행, 결과 노출, 저장/클릭 이벤트와 함께 호출되는지 회귀 검증한다.
- `/map`과 `/explore`의 지도 역할이 겹친다. 라우트를 제거하지 말고 진입 경로와 파라미터 사용처를 확인한 뒤 통합 여부를 결정한다.
- `/recommendation-test`는 실제 API를 사용하는 내부 QA 화면이다. 일반 사용자 메뉴에서는 숨기되 빌드에서 유지할지 개발 빌드 전용으로 제한할지 결정해야 한다.

## API 보존 체크

- 검색: 장소 검색, 구형 지도 검색 호환, AI 검색, 웹 검색, 안전 검사, 장소 목록.
- 대화: 세션 생성, 턴 전송, 세션 종료, 대화 토큰.
- 개인화: 검색 기록 조회·생성·삭제, 상호작용, 선호 조회·추가·삭제·재계산.
- 저장: 장소 조회·생성·수정·삭제, 그룹 조회·생성·수정·삭제, 그룹 이동.
- 제보: 생성, 사용자 목록·상세, 관리자 목록·상세·승인·반려.
- 커뮤니티: 게시글 CRUD·좋아요·신고, 댓글 CRUD·좋아요·싫어요·신고.
- 계정: 마이페이지, 닉네임, 프로필 사진, 로그인·가입·로그아웃.
- 알림·문의: 알림 조회·읽음·모두 읽음, 문의 생성·내 목록·상세, 관리자 목록·답변.
- 관리: 근거 큐·판정, 운영 현황, 회원 목록·상세·제재·알림, 커뮤니티 신고 처리.

## 구현 전 최종 대조 규칙

1. 각 라우트의 현재 버튼을 이 문서의 화면별 동작과 대조한다.
2. 새 시안에서 합쳐진 화면도 기존 API 호출과 권한 경계가 사라지지 않았는지 확인한다.
3. GET 화면은 로딩·빈 상태·오류·재시도를 확인하고, 변경 요청은 진행 중·성공·실패·중복 탭 방지를 확인한다.
4. 지도 검색은 검색어 결과 위치로 카메라가 이동하고, 지도 이동 후 재검색이 같은 검색 의도를 유지하는지 확인한다.
5. 관리자 승인 화면은 필수 입력값을 승인 버튼 가까이에 배치한다.
6. 구현 후 실제 단말에서 사용자·관리자 메뉴를 각각 전수 점검한다.
