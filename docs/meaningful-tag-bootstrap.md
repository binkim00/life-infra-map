# 의미 태그 전국 구축 파이프라인

## 원칙

`카페`, `식당`, `도서관`, `화장실` 같은 장소 분류는 의미 태그 시드로 세지 않는다.
태그는 지도 검색 API에서 바로 알기 어려운 운영·시설·접근성·경험 속성만 저장한다.
모든 태그 증거에는 장소, 출처, 원문 필드 또는 근거 요약, 관측일, 신뢰도와 만료일을 남긴다.

## 수집 경로

### 공식 구조화 데이터

- 관광공사 상세정보: 주차, 예약, 포장, 유아시설, 카드결제, 반려동물, 접근성
- 도서관·문화시설 공공데이터: 운영시간, 휴관일, 열람·어린이·장애인 시설
- 공원·주차장·화장실 표준데이터: 무료 여부, 놀이·운동·편의시설, 장애인 시설
- 사업자 또는 장소 소유자 입력: 시설과 운영 속성을 검증 가능한 방식으로 갱신

공식 필드는 `confirmed`, `is_verified=true`로 저장할 수 있다. 단, 빈 값이나
`없음`, `불가`, `미보유`는 긍정 태그로 만들지 않는다.

### 주관적 경험 데이터

`조용함`, `작업하기좋음`, `분위기좋음`, `혼밥좋음`, `데이트좋음`,
`대화하기좋음`, `전망좋음`, `웨이팅적음`은 자동 확정하지 않는다.

1. 검색 이벤트에서 자연어와 별칭을 표준 태그로 정규화한다.
2. 결과에 노출된 장소별로 `TagEnrichmentRequest`를 생성한다.
3. 같은 수요가 반복되면 작업 우선순위를 올린다.
4. 웹 검색 작업자가 장소명과 주소가 일치하는 출처만 사용한다.
5. URL, 근거 요약, 긍정·부정, 관측일을 `PlaceTagEvidence`에 저장한다.
6. 웹 근거 한 건은 신뢰도 55의 `candidate`로만 저장하고 120일 뒤 만료한다.
7. 사용자 명시 확인과 서로 독립적인 복수 근거를 모아야 확정으로 승격한다.

## 실행 명령

```powershell
# 기존 공식 원문에서 의미 태그 생성
python manage.py generate_meaningful_place_tags --source citypark_standard
python manage.py generate_meaningful_place_tags --source public_parking_standard

# 관광공사 상세 필드 보강. 중단 시 마지막 ID 다음부터 재시작한다.
python manage.py sync_tourapi_tag_details --limit 100 --after-id 0

# 검색 수요가 높은 주관 태그부터 근거 검색
python manage.py process_tag_enrichment_queue --limit 10
```

주관 태그 작업자는 일반 장소 검색과 별도로 아래 환경변수를 사용한다.

```env
TAG_ENRICHMENT_ENABLED=true
TAG_ENRICHMENT_PROVIDER=naver_search
```

초기에는 한 번에 10건 이하로 실행하고 비용·근거 채택률을 확인한 뒤 주기를 조정한다.
네이버 검색 결과가 부족하거나 문맥 판별이 어려운 태그만 `openai` 공급자로 재검증한다.

관광공사 API는 `DATA_GO_KR_TOUR_SERVICE_KEY`를 우선 사용하고, 없으면
`DATA_GO_KR_SERVICE_KEY`를 사용한다. 개발 계정 쿼터를 고려해 작은 배치로 실행한다.
