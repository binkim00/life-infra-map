# 추천 시나리오 정의

## 1. 문서 목적

본 문서는 상황 기반 생활 장소 추천 지도 서비스에서 우선 검토할 추천 시나리오를 정리한다.

본 서비스는 단순히 장소 카테고리를 조회하는 것이 아니라, 사용자의 현재 상황과 목적을 추천 조건으로 변환하여 적합한 장소를 추천하는 것을 목표로 한다.

---

## 2. 서비스 차별화 방향

- 사용자가 카테고리를 직접 고르지 않아도 상황에 맞는 장소를 추천한다.
- 장소의 거리, 카테고리, 태그, 데이터 신뢰도를 조합해 추천 점수를 계산한다.
- 공중화장실, 공공와이파이, 공원 같은 기본 생활 인프라는 단순 조회가 아니라 추천 근거 또는 보조 정보로 활용한다.
- 확정하기 어려운 정보는 `후보 태그`로 관리하고, 추천 이유에서도 단정하지 않는다.

---

## 3. MVP 우선 구현 시나리오

## 3.1 약속 전 시간 때우기 좋은 장소 추천

### 사용자 상황

약속 시간까지 남은 시간을 보낼 수 있는 가까운 장소가 필요하다.

### 추천 대상

- 카페
- 공원
- 쉼터
- 공공시설
- 무료 와이파이 주변 장소

### 주요 태그

`잠깐쉬기`, `대기하기좋음후보`, `실내`, `야외`, `무료`, `와이파이`, `화장실`

### 초기 구현 방식

현재 위치와 가까운 장소를 우선 추천하고, 사용자가 입력한 예상 대기 시간에 따라 거리 점수와 체류 가능성 태그를 반영한다.

---

## 3.2 조용히 작업할 카페 추천

### 사용자 상황

노트북 작업이나 공부를 하기 위해 조용하고 머물기 좋은 카페를 찾고 있다.

### 추천 대상

- 카페
- 도서관 주변 카페
- 공공 와이파이 주변 카페 후보

### 주요 태그

`작업가능후보`, `와이파이`, `콘센트후보`, `조용함후보`, `혼자이용후보`

### 초기 구현 방식

카페 후보 데이터에 직접 확인 태그 또는 관리자 입력 태그를 일부 부여하고, 태그 일치도와 거리 점수를 기준으로 추천한다.

---

## 3.3 근처 산책/힐링 장소 추천

### 사용자 상황

가볍게 산책하거나 머리를 식힐 수 있는 장소가 필요하다.

### 추천 대상

- 도시공원
- 하천변
- 쉼터
- 관광지
- 명소 후보

### 주요 태그

`산책`, `휴식`, `야외`, `자연친화`, `힐링`, `경관후보`

### 초기 구현 방식

도시공원, 쉼터, 관광지 데이터를 기반으로 산책과 휴식 태그를 부여하고, 거리와 편익시설 정보를 추천 점수에 반영한다.

---

## 3.4 흡연 가능한 장소 추천

### 사용자 상황

현재 위치 근처에서 흡연 가능한 장소가 필요하다.

### 추천 대상

- 흡연구역
- 흡연실
- 실외 흡연 가능 장소 후보

### 주요 태그

`흡연`, `흡연구역`, `실외`, `실내`, `개방형`, `폐쇄형`, `관리됨`

### 초기 구현 방식

좌표가 있는 흡연구역 데이터를 우선 사용하고, 거리 점수와 데이터 출처 신뢰도를 기준으로 추천한다.

---

## 4. 고도화 후보 시나리오

## 4.1 드라이브 목적지 후보 추천

### 사용자 상황

가볍게 다녀올 수 있는 드라이브 목적지가 필요하다.

### 추천 대상

- 관광지
- 전망대
- 공원
- 호수
- 해안
- 하천변

### 주요 태그

`드라이브후보`, `경관후보`, `야외`, `휴식`, `주차가능`

### 보류 이유

실제 드라이브 적합성, 도로 경관, 주차 난이도를 판단할 데이터가 부족하므로 고도화 기능으로 둔다.

---

## 4.2 야경 보기 좋은 장소 후보 추천

### 사용자 상황

밤에 가볍게 방문할 수 있는 야경 감상 장소가 필요하다.

### 추천 대상

- 전망대
- 공원
- 하천변
- 관광지
- 명소 후보

### 주요 태그

`야경후보`, `경관후보`, `야외`, `산책`, `드라이브후보`

### 보류 이유

야경 품질, 야간 개방 여부, 야간 안전성을 확정하기 어려우므로 `야경후보`로만 관리한다.

---

## 4.3 비 오는 날 갈 만한 장소 추천

### 사용자 상황

비가 오는 날에도 이용하기 좋은 실내 장소가 필요하다.

### 추천 대상

- 카페
- 도서관
- 공공시설
- 문화시설
- 실내 쉼터

### 주요 태그

`실내`, `작업가능후보`, `휴식`, `공공시설`, `카페`

### 보류 이유

날씨 연동과 실내 장소 데이터 보강이 필요하므로 고도화 기능으로 둔다.

---

## 4.4 혼자 있기 좋은 장소 추천

### 사용자 상황

혼자 조용히 시간을 보내거나 부담 없이 머물 장소가 필요하다.

### 추천 대상

- 카페
- 공원
- 도서관
- 쉼터
- 산책 장소

### 주요 태그

`혼자이용후보`, `조용함후보`, `휴식`, `산책`, `작업가능후보`

### 보류 이유

분위기, 혼잡도, 좌석 구조를 확인하기 어려우므로 초기에는 후보 태그로만 관리한다.

---

## 4.5 이동 중 급한 상황 해결 장소 추천

### 사용자 상황

이동 중 급하게 화장실, 흡연구역, 주차장 등 생활 편의 장소가 필요하다.

### 추천 대상

- 공중화장실
- 흡연구역
- 주차장
- 공공시설

### 주요 태그

`급할때`, `생활불편해결`, `화장실`, `흡연`, `주차가능`, `24시간`

### 보류 이유

단순 생활 인프라 조회처럼 보일 수 있으므로, MVP 핵심보다는 보조 시나리오로 활용한다.

---

## 5. MVP 우선순위

| 우선순위 | 시나리오 | 판단 |
|---|---|---|
| 1 | 약속 전 시간 때우기 좋은 장소 추천 | 상황 기반 추천 차별성이 큼 |
| 2 | 조용히 작업할 카페 추천 | 사용자 니즈가 명확함 |
| 3 | 근처 산책/힐링 장소 추천 | 공공데이터와 추천 로직을 함께 활용 가능 |
| 4 | 흡연 가능한 장소 추천 | 생활 불편 해결형으로 차별성이 있음 |

---

## 6. 초기 구현 제외 기준

초기 구현에서는 아래 내용을 확정 정보로 제공하지 않는다.

- 조용한 카페 확정
- 콘센트 있음 확정
- 노트북 작업 가능 확정
- 야경 명소 확정
- 드라이브 코스 확정
- 실시간 주차 가능 여부
- 실시간 혼잡도
- 현재 운영 여부

위 정보들은 데이터로 직접 확인되지 않는 경우 `후보 태그` 또는 고도화 기능으로 관리한다.

## 실시간 검색 결과 태그 부여 방식

본 서비스는 모든 장소 데이터를 자체 DB에 저장하지 않는다.

카페, 관광지, 드라이브 목적지 후보, 야경 후보처럼 자체 데이터 확보가 어려운 장소는 지도 API의 실시간 장소 검색 결과를 활용할 수 있다.

지도 API 검색 결과에는 추천 시점에 임시 태그를 부여한다.

임시 태그는 추천 점수 계산과 결과 표시에는 활용하지만, 별도 검증이나 사용자 저장이 없는 경우 DB에 영구 저장하지 않는다.

자체 DB에는 공공데이터 기반 장소, 팀이 직접 확인한 장소, 관리자 검증 장소, 사용자 저장 또는 검증을 통해 관리가 필요한 장소만 저장한다.

| 구분 | 저장 위치 | 설명 |
|---|---|---|
| verified_tags | DB PlaceTag | 검증된 장소 태그 |
| runtime_tags | API 응답 메모리 | 지도 API 검색 결과에 임시 부여하는 태그 |
| scenario_scores | 추천 계산 결과 | 거리, 상황 적합도 등 요청마다 달라지는 점수 |
