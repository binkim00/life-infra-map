# 추천 가치 태그 전략

## 1. 문서 목적

이 문서는 상황 기반 장소 추천 서비스에서 추천 가치 태그를 어떻게 정의하고, 확보하고, 검증하고, 추천 점수에 반영할지 정리하기 위한 문서입니다.

본 서비스는 단순히 지도 API 검색 결과를 보여주는 것이 아니라, 장소별 태그의 출처와 검증 상태를 관리하여 사용자의 상황에 더 적합한 장소를 추천하는 것을 목표로 합니다.

## 2. 태그 구분

### 카테고리/필터용 태그

장소의 종류를 구분하거나 기본 필터에 사용하는 태그입니다.

예시:
- 카페
- 공원
- 흡연구역
- 공중화장실
- 주차장
- 무료 와이파이

### 추천 가치 태그

사용자의 상황과 직접 연결되어 추천 품질을 결정하는 태그입니다.

예시:
- 혼자 이용 좋음
- 오래 머물기 좋음
- 조용함
- 노트북 작업 가능
- 콘센트 있음
- 와이파이 있음
- 분위기 좋음
- 산책하기 좋음
- 야경 보기 좋음

### 상태/주의 태그

추천 점수 보정이나 사용자 안내에 사용하는 태그입니다.

예시:
- 좌석 확인 필요
- 콘센트 확인 필요
- 와이파이 확인 필요
- 운영 정보 확인 필요
- 위치 확인 필요
- 테이크아웃 가능성

## 3. 태그 저장 기준

모든 지도 API 검색 결과를 DB에 저장하지 않습니다.

DB 저장 대상:
- 자체 수집 데이터
- 팀이 직접 확인한 장소
- 사용자가 저장한 장소
- 사용자 또는 관리자가 검증한 장소

지도 API 검색 결과는 기본적으로 DB에 저장하지 않고, 추천 시점에 임시 태그를 부여한 후보 장소로만 사용합니다.

## 4. 태그 출처

| 출처 | 설명 |
|---|---|
| category_rule | 카테고리 기반 자동 태그 |
| runtime_rule | 추천 시점에 임시로 붙이는 규칙 기반 태그 |
| ai_suggested | AI가 제안한 후보 태그 |
| external_data | 외부 데이터 원본에서 확인 가능한 태그 |
| admin_checked | 팀 또는 관리자가 확인한 태그 |
| user_verified | 사용자 검증 기반 태그 |

## 5. 태그 상태

| 상태 | 설명 |
|---|---|
| confirmed | 확인 근거가 있어 추천 점수에 강하게 반영 가능한 태그 |
| candidate | 가능성은 있지만 아직 확정되지 않은 후보 태그 |
| needs_verification | 확인이 필요한 태그 |
| rejected | 검증 결과 맞지 않는 것으로 판단된 태그 |

## 6. AI 활용 방식

AI는 실제 장소 정보를 생성하거나 태그를 확정하지 않습니다.

AI 활용 범위:
- 사용자 자연어 입력을 추천 태그 조건으로 변환
- 장소명, 카테고리, 설명, 확인 메모를 기반으로 후보 태그 제안
- 추천 결과에 대한 추천 이유 문장 생성

AI가 생성한 태그는 `ai_suggested` 출처와 `candidate` 상태로 저장하며, 확인 과정을 거쳐야만 `confirmed` 상태로 전환합니다.

## 7. 추천 점수 반영 방향

추천 점수는 태그의 출처와 상태에 따라 다르게 반영합니다.

예시:
- confirmed 태그 일치: 높은 가점
- candidate 태그 일치: 낮은 가점
- runtime 임시 태그 일치: 후보 판단용으로만 약하게 반영
- needs_verification 태그: 감점 또는 안내 문구 표시
- rejected 태그: 추천에서 제외하거나 강한 감점

## 8. 지도 API 후보와 DB 저장 장소의 차이

지도 API 결과는 추천 후보를 넓히는 용도로 사용합니다.  
DB 저장 장소는 태그 출처와 검증 상태를 관리할 수 있으므로 추천 점수에서 더 높은 신뢰도를 가집니다.

따라서 추천 결과는 다음 우선순위를 가집니다.

1. 검증 태그가 있는 DB 저장 장소
2. 후보 태그가 있는 DB 저장 장소
3. 자체 수집 데이터 기반 장소
4. 지도 API 기반 임시 후보 장소
