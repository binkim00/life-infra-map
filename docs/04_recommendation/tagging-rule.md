# 장소 태그 부여 규칙

## 1. 문서 목적

본 문서는 상황 기반 생활 장소 추천 지도 서비스에서 장소 태그를 어떤 기준으로 저장하고 추천에 반영할지 정의합니다.

태그는 단순한 표시용 단어가 아니라, 사용자의 상황에 맞는 장소를 추천하기 위한 판단 기준입니다. 따라서 모든 장소 설명을 태그로 저장하지 않고, 추천과 필터에 실제로 사용할 수 있는 세부 속성만 `PlaceTag`로 저장합니다.

---

## 2. 태그 저장 기본 원칙

### 2.1 카테고리만으로 알 수 있는 기본 태그는 저장하지 않음

`Place.category`만으로 이미 알 수 있는 태그는 `PlaceTag`에 저장하지 않습니다.

| 카테고리 | 저장하지 않는 기본 태그 예시 |
|---|---|
| `parking` | 주차장 |
| `city_park` / `citypark` | 공원, 도시공원 |
| `beach` | 해수욕장, 바다 |
| `toilet` | 공중화장실, 생활편의 |
| `shelter` | 쉼터 |
| `free_wifi` | 무료와이파이, 와이파이 |
| `smoking_area` | 흡연구역, 흡연, 흡연가능 |

카테고리 정보는 `Place.category`에서 관리하고, `PlaceTag`에는 추천과 필터에 도움이 되는 세부 속성만 저장합니다.

---

### 2.2 추천/필터에 사용할 세부 속성만 저장

`PlaceTag`에 저장할 수 있는 태그는 사용자가 장소를 고를 때 실제 판단 근거가 되는 정보입니다.

| 분야 | 저장할 수 있는 세부 태그 예시 |
|---|---|
| 주차장 | 무료주차, 유료주차, 공영주차장, 야간운영후보, 24시간운영후보, 장애인주차구역있음 |
| 공중화장실 | 장애인화장실있음, 기저귀교환대있음, 비상벨있음, CCTV있음, 24시간개방후보 |
| 쉼터 | 냉방시설있음, 실내쉼터, 야간운영후보, 주말휴일개방, 수용인원많음 |
| 도시공원 | 운동시설, 놀이시설, 주차가능, 산책좋음, 사진찍기좋음, 야경 |
| 해수욕장 | 모래해변, 긴해변, 넓은해변, 야경, 드라이브목적지, 사진찍기좋음 |
| 관광지 | 산책좋음, 힐링, 야경, 사진찍기좋음, 혼자이용좋음, 드라이브목적지 |
| 카페 후보 | 노트북작업, 조용한, 콘센트있음, 와이파이, 혼자이용좋음, 루프탑 |
| 흡연구역 | 실내흡연실, 실외흡연구역, 부스형흡연구역, 개방형흡연구역 |

---

### 2.3 확정 정보와 후보 정보를 구분

공공데이터 원본 필드에서 직접 확인 가능한 정보는 상대적으로 신뢰도가 높습니다. 반면 블로그 검색, 키워드 규칙, AI 제안은 확정 정보가 아니라 후보 정보로 저장합니다.

| status | 설명 | 추천 반영 |
|---|---|---|
| `confirmed` | 원본 필드 또는 검수로 확인된 태그 | 강하게 반영 |
| `candidate` | 가능성은 있으나 확정되지 않은 후보 태그 | 약하게 반영 |
| `needs_verification` | 정보 부족 또는 확인이 필요한 태그 | 안내 또는 감점 |
| `rejected` | 검수 결과 부적절한 태그 | 제외 |

---

## 3. 태그 source 기준

현재 `kyb` 브랜치의 `PlaceTag.source` 기준은 다음과 같습니다.

| source | 설명 | 사용 예시 |
|---|---|---|
| `category_rule` | 카테고리 기반 규칙 태그. 단, 너무 기본적인 태그는 저장하지 않음 | 세부 분류 성격이 있는 경우만 제한적으로 사용 |
| `field_rule` | 공공데이터 원본 필드에서 나온 태그 | 무료주차, 장애인화장실있음, 냉방시설있음 |
| `keyword_rule` | 장소명, 시설명, 주소, 설명의 키워드로 붙인 태그 | 공원화장실, 교통시설화장실 |
| `blog_search` | 블로그 검색 결과 기반 후보 태그 | 야경, 산책좋음, 사진찍기좋음 |
| `external_api` | 카카오, 관광공사 등 외부 API 응답 기반 태그 | 외부 API 보강 태그 |
| `external_data` | CSV, JSON, 지자체 데이터 등 외부 원본 데이터 기반 태그 | 흡연구역 세부 유형, 기존 외부 데이터 태그 |
| `ai_suggested` | AI가 추천한 후보 태그 | 후보 태그 생성 |
| `checked` | 팀 또는 관리자 검수 완료 태그 | 검수 완료 태그 |
| `user_verified` | 사용자 검증 태그 | 운영 후 사용자 검증 |
| `warning_tags` | 확인 필요 태그 | 운영시간확인필요, 요금정보확인필요 |

현재 모델은 `team_checked`와 `admin_checked`를 나누지 않고 `checked`로 관리합니다. 추후 관리 권한을 세분화할 필요가 있으면 `team_checked`, `admin_checked`로 분리할 수 있습니다.

---

## 4. 화면/API 출력 그룹 기준

DB에는 source를 세분화해서 저장하지만, 화면에서는 사용자가 이해하기 쉽게 묶어서 보여줍니다. `display_group`은 별도 DB 필드로 저장하지 않고 serializer 또는 모델 메서드에서 계산합니다.

| 화면 출력 그룹 | 포함 조건 |
|---|---|
| 검수 태그 | `source=checked` |
| 데이터 기반 태그 | `category_rule`, `field_rule`, `keyword_rule`, `external_data`, `external_api` |
| 블로그 태그 | `source=blog_search` |
| AI 후보 태그 | `source=ai_suggested` |
| 사용자 검증 태그 | `source=user_verified` |
| 확인 필요 태그 | `status=needs_verification` 또는 `tag_type=warning` 또는 `source=warning_tags` |

---

## 5. 카테고리별 태그 처리 기준

### 5.1 무료와이파이

무료와이파이는 위치 데이터 자체가 핵심입니다. `Place.category = free_wifi`만으로 사용 목적이 충분히 표현되므로 별도 `PlaceTag` seed는 생성하지 않습니다.

저장하지 않는 태그:

```text
무료와이파이
와이파이
인터넷사용
무선인터넷
```

단, 무료와이파이 데이터만으로 `노트북작업가능`, `조용함`, `콘센트있음`을 확정하지 않습니다.

---

### 5.2 흡연구역

흡연구역도 위치 데이터가 핵심입니다. `흡연구역`, `흡연`, `흡연가능` 같은 기본 태그는 저장하지 않습니다.

원본 데이터에서 세부 유형이 명확할 때만 다음 태그를 저장합니다.

| 조건 | 저장 태그 | source | status |
|---|---|---|---|
| 실내/실내형 | 실내흡연실 | external_data 또는 field_rule | confirmed |
| 실외/옥외/외부/야외 | 실외흡연구역 | external_data 또는 field_rule | confirmed |
| 부스/흡연부스 | 부스형흡연구역 | external_data 또는 field_rule | confirmed |
| 개방/개방형/노천 | 개방형흡연구역 | external_data 또는 field_rule | confirmed |

`관리:기관명`, `상태:...`, `제보유형:...` 같은 값은 추천 태그가 아니라 메타데이터에 가까우므로 `PlaceTag`로 저장하지 않습니다.

---

### 5.3 공중화장실

공중화장실은 카테고리 자체를 나타내는 태그를 제거하고, 실제 이용 편의에 영향을 주는 세부 태그만 저장합니다.

저장하지 않는 태그:

```text
공중화장실
생활편의
오물처리방식정보있음
남녀화장실정보있음
연락처있음
개방시간정보있음
```

저장 대상 예시:

```text
장애인화장실있음
기저귀교환대있음
비상벨있음
CCTV있음
24시간개방후보
개방화장실
비상벨확인필요
```

---

### 5.4 주차장

`주차장` 기본 태그는 저장하지 않습니다. 요금, 운영시간, 주차장 유형처럼 사용자가 실제 판단할 수 있는 태그만 저장합니다.

저장 대상 예시:

```text
무료주차
유료주차
공영주차장
민영주차장
노상주차장
노외주차장
부설주차장
24시간운영후보
야간운영후보
장애인주차구역있음
요금정보확인필요
```

실시간 주차 가능 대수는 초기 구현 범위에 포함하지 않습니다.

---

### 5.5 도시공원

`공원`, `도시공원`처럼 카테고리만으로 알 수 있는 태그는 저장하지 않습니다. 추천에 의미 있는 세부 속성만 저장합니다.

저장 대상 예시:

```text
운동시설
놀이시설
편의시설
주차가능
산책좋음
사진찍기좋음
힐링
야경
반려동물동반
```

도시공원 데이터만으로 `조용함`, `데이트좋음` 등을 확정하지 않습니다. 블로그 기반 태그는 후보로 관리합니다.

---

### 5.6 해수욕장

`해수욕장`, `바다`처럼 카테고리만으로 알 수 있는 태그는 저장하지 않습니다.

저장 대상 예시:

```text
모래해변
몽돌해변
자갈해변
긴해변
넓은해변
야경
드라이브목적지
사진찍기좋음
서핑
반려동물동반
```

---

### 5.7 쉼터

`쉼터`는 기본 태그로 제거합니다. `무더위쉼터`는 현재 seed에 남아 있으나 카테고리 성격이 강하므로 최종 import 전에 제외 여부를 다시 확인합니다.

저장 대상 예시:

```text
냉방시설있음
실내쉼터
야간운영후보
주말휴일개방
수용인원많음
숙박가능후보
한파쉼터후보
운영시간확인필요
```

---

### 5.8 카페 후보

카페는 현재 `Place`로 저장하지 않고, 카카오 Local API 검색 결과와 매칭할 수 있는 `ExternalPlaceTag` 후보로 관리합니다.

블로그 기반 태그는 확정 정보가 아니라 후보 정보입니다.

저장 대상 예시:

```text
노트북작업
조용한
콘센트있음
와이파이
혼자이용좋음
루프탑
야경
웨이팅주의
```

---

### 5.9 관광지

관광공사 기반 공식 관광지는 `Place`로 저장 가능하며, 블로그 기반 태그는 `PlaceTag` 후보로 저장합니다.

저장 대상 예시:

```text
사진찍기좋음
힐링
산책좋음
혼자이용좋음
데이트좋음
야경
드라이브목적지
```

---

## 6. 추천 점수 반영 기준

초기 추천 점수는 규칙 기반으로 계산합니다.

```text
추천 점수 =
카테고리 일치 점수
+ 태그 일치 점수
+ 거리 점수
+ 태그 신뢰도 점수
+ 최신 확인 점수
- 확인 필요/오류 제보 감점
```

태그 상태별 반영 강도는 다음과 같습니다.

| 상태 | 반영 방식 |
|---|---|
| confirmed | 강하게 반영 |
| candidate | 약하게 반영 |
| needs_verification | 안내 또는 감점 |
| rejected | 제외 |

---

## 7. 확정 태그로 사용하지 않을 정보

현재 수집 데이터만으로 아래 정보는 확정 태그로 사용하지 않습니다.

```text
조용함
노트북작업가능
콘센트있음
카페작업좋음
혼자이용좋음
야경좋음
분위기좋음
붐비지않음
실시간이용가능
실시간주차가능
현재이용가능
```

단, 블로그 검색 기반 후보, 팀 검수, 관리자 검수, 사용자 검증이 붙는 경우에는 상태와 source를 구분하여 저장할 수 있습니다.
