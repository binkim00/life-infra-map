# 장소 태그 자동 부여 규칙

## 1. 문서 목적

본 문서는 수집한 장소 데이터에 태그를 자동으로 부여하는 기준을 정의한다.

본 서비스에서 태그는 단순한 표시 정보가 아니라, 사용자의 상황에 맞는 장소를 추천하기 위한 핵심 기준이다.

따라서 태그는 부여 근거, 출처, 신뢰도를 함께 관리한다.

---

## 2. 태그 부여 기본 원칙

장소에 태그를 부여할 때는 다음 원칙을 따른다.

- 원본 데이터로 확인 가능한 정보만 확정 태그로 부여한다.
- 카테고리만으로 판단 가능한 기본 태그는 자동 부여한다.
- 원본 컬럼값으로 확인 가능한 정보는 높은 신뢰도로 부여한다.
- 장소명이나 설명의 키워드로 추론한 태그는 낮은 신뢰도로 부여한다.
- AI가 생성한 태그는 확정 정보가 아니라 후보 태그로 관리한다.
- 조용함, 콘센트 있음, 노트북 작업 가능처럼 실제 확인이 어려운 정보는 확정 태그로 부여하지 않는다.

---

## 3. 태그 부여 출처

| source | 설명 | 신뢰도 기준 |
|---|---|---:|
| category_rule | 카테고리 기반 자동 태그 | 80~100 |
| field_rule | 원본 컬럼 기반 태그 | 85~100 |
| keyword_rule | 장소명/설명 키워드 기반 추론 태그 | 50~75 |
| ai_suggested | AI 추천 후보 태그 | 40~60 |
| admin_verified | 관리자 확인 태그 | 100 |
| user_verified | 사용자 검증 태그 | 70~90 |
| public_data | 공공데이터에서 직접 확인 가능한 태그 | 90~100 |

---

## 4. 추천 반영 기준

| 태그 상태 | 추천 반영 방식 |
|---|---|
| 공공데이터 기반 확정 태그 | 강하게 반영 |
| 원본 컬럼 기반 태그 | 강하게 반영 |
| 카테고리 기반 기본 태그 | 보통 반영 |
| 키워드 기반 추론 태그 | 약하게 반영 |
| AI 후보 태그 | 약하게 반영 또는 후보 표시 |
| 관리자 확인 태그 | 강하게 반영 |
| 사용자 검증 태그 | 검증 수에 따라 반영 |

## 7. 키워드 기반 추론 태그

장소명, 시설명, 상세주소, 설명 등에 특정 키워드가 포함된 경우 추론 태그를 부여할 수 있다.

단, 키워드 기반 태그는 확정 정보가 아니므로 낮은 신뢰도로 저장한다.

| 키워드 | 부여 태그 | confidence | 설명 |
|---|---|---:|---|
| 공원 | 산책 | 70 | 공원명 기반 추론 |

| 어린이공원 | 어린이이용 | 75 | 공원명 기반 추론 |
| 체육공원 | 운동 | 75 | 공원명 기반 추론 |
| 하천 | 산책 | 65 | 주변 환경 기반 추론 |
| 천변 | 산책 | 65 | 주변 환경 기반 추론 |
| 전망대 | 경관후보 | 60 | 야경 확정 아님 |

| 주민센터 | 공공시설 | 75 | 시설명 기반 추론 |

## 8. 확정 태그로 사용하지 않을 정보

현재 수집 데이터만으로 아래 태그는 확정 태그로 사용하지 않는다.

```txt
조용함
노트북작업가능
콘센트있음
카페작업좋음
혼자이용좋음
야경좋음
분위기좋음
붐비지않음
실시간이용가능
실시간주차가능
현재이용가능
```

위 정보들은 공공데이터 또는 현재 수집 데이터에서 직접 확인하기 어렵다.

추후 관리자 확인, 사용자 검증, 별도 데이터 확보가 있을 경우에만 신뢰도 높은 태그로 전환한다.

## 10. 추천 점수와의 연결

태그는 추천 점수 계산에 사용된다.

초기 추천 점수는 다음 요소를 조합하여 계산한다.

```txt
추천 점수 =
카테고리 일치 점수
+ 태그 일치 점수
+ 거리 점수
+ 태그 신뢰도 점수
+ 최신 확인 점수
- 오류 제보 감점
```

태그 일치 점수는 사용자의 상황 또는 선택 조건과 장소 태그가 얼마나 일치하는지를 기준으로 계산한다.

태그 신뢰도 점수는 PlaceTag의 `confidence`를 기반으로 계산한다.

## 11. 태그 부여 처리 흐름

장소 데이터 import 시 태그 부여 흐름은 다음과 같다.

```txt
외부 데이터 읽기
→ 데이터 정제
→ Place 생성
→ 카테고리 기본 태그 부여
→ 원본 컬럼 기반 태그 부여
→ 키워드 기반 추론 태그 부여
→ PlaceTag에 source, confidence, evidence 저장
```

AI 태그 후보 생성은 초기 필수 구현이 아니라 고도화 기능으로 둔다.

## 12. 초기 구현 범위

초기 구현에서 사용할 태그 부여 방식은 다음으로 제한한다.

| 방식 | 초기 구현 여부 |
|---|---|
| 카테고리 기반 태그 | O |
| 원본 컬럼 기반 태그 | O |
| 키워드 기반 추론 태그 | O |
| AI 후보 태그 | 선택 |
| 관리자 확인 태그 | 선택 |
| 사용자 검증 태그 | 선택 |

초기 구현의 목표는 완벽한 태그 자동화가 아니라, 수집한 데이터의 명확한 근거를 바탕으로 추천 가능한 기본 태그를 안정적으로 부여하는 것이다.
