# 여기일지도 Play 비공개 테스터 참여 안내

여기일지도의 Android 비공개 테스트에 참여하고 검색·위치·저장·초안 동작의 의견을 모으기 위한 안내다. 2026년 10월 14일 Play Console에서 Alpha 트랙 활성, 기존 버전 1.0.2 코드 5 제공, 참여 선택 0명을 확인했다. 최신 master c58d885c의 정식 1.0.2 코드 6 AAB는 생성·Play 등록 업로드 서명·16KB 정렬 검증까지 완료했다. 새 AAB 업로드 및 테스트 버전 반영은 별도로 완료한 뒤 해당 버전으로 시험한다.

최종 제출 후보는 [등록 업로드 키로 서명한 code6 AAB](../artifacts/local-builds/lifemap-production-code6-master-c58d885c-20261014.aab)이며 SHA256은 `35c393f47f7adf8d435b3933da5cb202f5eb366f188329bc4fb18c0145981ae4`다. EAS 원격 원본은 다른 기존 기본 키로 서명돼 있으므로 최종 제출 후보와 혼동하지 않는다.

## 참여와 설치

### 2026-10-14 링크 접근 진단

- code6는 Alpha 검토 중이며 기존 code5는 선택한 테스터에게 계속 제공됨을 콘솔에서 확인했다. 새 버전 심사 대기만으로 기존 참여 링크 전체가 막힌 상태는 아니다.
- 현재 로그인 계정으로 웹 참여 링크에서 여기일지도와 `Become a tester` 버튼이 표시되고, 설치 링크에서 여기일지도와 설치 버튼이 표시됐다. 참여 버튼이나 설치 버튼은 누르지 않았다. 외부 테스터 계정의 실제 접근 성공은 별도로 확인해야 한다.
- Alpha 허용 대상은 tester-match@googlegroups.com 한 그룹이다. 그룹 about 화면에서 웹의 모든 사용자에게 그룹 열람·가입 허용을 확인했다. 현재 로그인 계정은 그룹 회원이다. 회원 수는 앱 참여자 수가 아니다.
- Alpha 제공 국가는 대한민국 한 곳이다. 해외 Play 국가 계정은 그룹 회원이어도 접근이 제한될 수 있다. 오픈채팅 회원이라는 사실만으로 Google 그룹 회원 자격은 생기지 않는다.
- 공유 순서: 그룹 가입 링크 → 같은 Play 계정으로 웹 테스트 참여 → 설치 링크. 카카오톡 안에서 다른 계정으로 열린 경우 Chrome에서 Play 스토어와 같은 계정인지 확인한다. 기존 내부 테스트 참여자는 내부 테스트를 나간 후 비공개 테스트에 참여해야 한다.
- 당시 공유 링크·오류 문구를 아직 받지 못했으므로 과거 실패의 단일 원인은 확정하지 않았다. 콘솔·그룹·계정·국가 설정은 진단 중 변경하지 않았다.

1. Android Play 스토어에서 사용할 Google 계정을 확인한다.
2. [tester-match Google 그룹](https://groups.google.com/g/tester-match)의 회원 자격을 확인한다. 현재 Alpha의 허용 대상은 `tester-match@googlegroups.com`이다. 그룹 가입이 필요한 계정은 화면의 가입 또는 신청 절차를 완료한다.
3. 같은 Google 계정으로 [여기일지도 비공개 테스트 참여 페이지](https://play.google.com/apps/testing/com.binkim00.lifeinframap)를 열고 테스트 참여를 선택한다.
4. [Play 스토어 설치 페이지](https://play.google.com/store/apps/details?id=com.binkim00.lifeinframap)에서 여기일지도를 설치한다. 설치가 안 되면 Play 스토어 계정과 그룹·참여 페이지의 계정이 같은지 확인한다.
5. 앱 설정에서 버전을 확인하고 아래 항목을 시험한다. 참가를 선택한 상태는 최소 14일 연속 유지한다.

그룹 회원 자격, 테스트 참여 선택, 설치는 별도 단계다. 테스트 시작일은 초대 발송일이 아니라 각 계정이 실제 참여를 선택한 날짜로 기록한다. 그룹 회원 수를 이 앱의 참여 테스터 수로 기록하지 않는다.

## 첫날 시험 항목

| 항목 | 시험 순서 | 확인할 결과 |
|---|---|---|
| 실행과 위치 | 앱 실행 → 위치 권한 허용 → 주변 장소 → 위치 다시 시도 | 무한 로딩 없이 결과 또는 이해 가능한 안내 |
| 권한 거부 | 앱 위치 권한을 거부한 상태로 지역명 검색 | 수동 지역 검색 가능, 권한 허용 후 복구 |
| 검색 | 지역명·카페 검색 → 필수조건 추가·제거 → 결과 확인 | 검색문·조건 유지, 근거 부족은 부족으로 안내 |
| 뒤로 이동 | 검색 결과 → 장소 상세 → Android 뒤로 → 검색 또는 홈 | 패널·키보드·화면의 순서에 맞게 복귀 |
| 저장 | DB 장소와 외부 장소를 각각 저장 → MY 확인 → 저장 해제 | 올바른 장소가 표시되고 저장·해제 상태 일치 |
| 제보 초안 | 별도의 시험 초안에 텍스트·태그·사진 입력 → 화면 이동·재실행 | 입력 복구, 다른 계정의 초안과 분리 |
| 사진 정리 | 시험 사진 여러 장 선택 → 교체·삭제 → 화면 재진입 | 미리보기와 남은 사진 수 일치 |
| 연결 복구 | 읽기 검색 중 네트워크 끄기 → 오류 확인 → 연결 복원·재시도 | 검색 상태 보존과 재시도 성공 |

제보·게시글 제출이나 사진 업로드는 개발자가 지정한 시험 대상이 있을 때만 수행한다. 개인 사진 대신 별도 시험 이미지를 사용한다. 실제 로그인 완료를 시험할 때는 본인 기기에서 직접 입력하고 비밀번호·인증번호·토큰을 피드백에 넣지 않는다.

## 14일 참여와 피드백

Google의 현재 개인 계정 요구사항은 최소 12명이 14일 연속 비공개 테스트 참여를 선택한 상태를 유지하는 것이다. 내부 테스트만으로 이 조건을 충족하지 않는다. [Google 공식 테스트 요구사항](https://support.google.com/googleplay/android-developer/answer/14151465?hl=ko)

- 첫날: 참여 선택·설치·버전 확인 및 위 핵심 흐름 시험.
- 이후: 앱을 실제 사용 목적에 맞게 사용하고 문제나 불편을 기록한다. 매일 실행 횟수를 공식 필수 조건으로 해석하지 않는다.
- 중간 점검: 검색·위치·초안에서 발견한 문제를 개발자와 공유하고 수정 버전이 제공되면 다시 확인한다.
- 종료 점검: Play Console의 참여자 수와 연속 참여 조건을 확인하고 피드백·수정 내역을 정리한다. 임의 날짜로 14일 충족을 미리 확정하지 않는다.

Google Play의 비공개 테스트 의견 또는 Alpha에 설정된 피드백 경로를 이용한다. 전달 내용은 아래 양식을 사용한다.

```text
기기 모델 / Android 버전:
앱 버전 / 버전 코드:
시험한 항목:
재현 순서:
기대한 결과:
실제 결과:
다시 발생하는지:
개인정보를 가린 화면 자료(선택):
```

정확한 현재 위치, 개인 사진, 계정 주소, 비밀번호·인증정보는 포함하지 않는다.

## 개발자 실행 목록

- 최신 수정본 정식 AAB의 package, 새 versionCode, 내용 서명, Play 업로드 키 일치, 16KB 조건 확인.
- 검증한 AAB를 내부 또는 Alpha에 반영할 구체적 버전·변경사항 준비. 업로드·게시·제출은 별도 실행 단계다.
- 모집 대상이 실제 그룹 회원이고 테스트 참여 링크를 열 수 있는지 확인.
- 초대는 대상과 발송 승인이 확정된 후 전달. 이 문서 작성으로 외부 초대나 신청을 발송하지 않았다.
- 개인 연락처를 공개 Git에 저장하지 않고 참여 시작일·앱 버전·피드백을 필요한 범위에서 관리.
- 최소 12명/14일 조건과 피드백 반영 후 프로덕션 액세스 신청 자료 준비.

현재 사실의 근거는 Play Console Alpha의 테스터 설정과 대시보드이며, 공식 절차는 [공개·비공개·내부 테스트 설정](https://support.google.com/googleplay/android-developer/answer/9845334?hl=ko)을 따른다.
