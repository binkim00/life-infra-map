# 네이버 플레이스 필터와 우리 근거·검색 비교

기준: 2026-09-30 저장소 코드와 사용자가 제공한 네이버 플레이스 필터 화면 3장. 네이버의 내부 판정 방식이나 운영 DB의 현재 태그별 보유량을 확인한 문서는 아니다. 화면에 보이는 필터 이름을 곧바로 개별 장소의 검증된 사실로 취급하지 않는다.

## 1. 현재 검색에서 근거가 쓰이는 방식

| 검색 경로 | 사용자가 하는 일 | 현재 적용 방식 | 해석할 때 주의할 점 |
| --- | --- | --- | --- |
| 지도 일반 검색 (`탐색`) | 검색어 입력 또는 주차장·화장실·공원·흡연구역 빠른 선택 | `place-search`/`map-search`가 이름·주소·업종·저장 태그명 등으로 후보를 찾고 카카오 장소 후보도 합친다. | 저장 태그명 텍스트 일치는 곧 확인된 조건 충족이 아니다. 모든 태그의 상태를 검증하는 네이버식 상세 필터가 아니다. |
| 조건 골라 찾기 | 지역, 6개 장소 종류, 상황, 5개 `꼭 필요한 조건` 중 선택 | 선택한 지역·종류·필수 조건을 `selected_filters`로 보내고 서버 허용 목록에서 `required_features`로 변환한다. 선택한 상황은 검색 문장에만 포함된다. | 5개는 고정된 초기 화면 목록일 뿐, 전체 근거 목록이나 특별히 검증된 5개가 아니다. 미선택 항목은 필수가 아니다. |
| 대화형 추천 검색 | 자연어로 장소와 상황·조건 설명 | 검색 계획이 지역·업종·조건을 해석하고 DB/외부 후보에 근거 태그를 붙여 조건을 평가한다. 일부 조건만 확인된 후보는 충족·미확인 조건을 나눠 표시할 수 있다. | 조건의 이름을 이해하는 것, 해당 장소에 현재 유효한 승인 근거가 있는 것, 최종 검색 결과에 남는 것은 각각 다른 단계다. 확인된 조건이 전혀 없으면 추가 질문으로 끝날 수 있다. |

근거 데이터는 원본 출처, 긍정·부정, 관찰·만료일, 검토 상태를 별도로 보관한다. 공식 필드의 긍정 근거는 확인 태그가 될 수 있지만 독립 웹 근거 2건은 기본적으로 후보 단계다. 제한 승인·만료 자료는 현재 필수 조건 충족으로 취급하지 않는다. 추천 카드에는 `근거 있음`, `확인 필요`, `과거 자료·현재 미확인`이 구분된다. **태그 정의, 수집 대상, 저장된 후보, 현재 유효한 확인 근거, 화면 필터는 같은 집합이 아니다.**

## 2. 네이버 화면 항목별 대조와 수집 판단

표의 `정의·수집 대상`은 코드가 해당 개념을 다룬다는 뜻이며, 모든 장소의 근거가 충분하다는 뜻은 아니다. `자연어`는 단어를 검색 계획이나 태그 후보로 해석할 수 있는 경로가 있다는 뜻이다. 실제 충족 판정은 장소별 승인·유효 근거가 있어야 한다.

| 네이버 화면 영역 | 우리 근거/검색의 현재 상태 | 더 모을 근거와 구분 방법 | 우선 |
| --- | --- | --- | --- |
| 정렬: 많이 찾는·요즘 뜨는·TV에 나온·리뷰 많은 | 현재 선택형 조건이나 장소 근거 태그로 연결되지 않는다. | 방문·리뷰 지표나 방송 이력은 별도 순위/출처 데이터다. 타 플랫폼의 노출 순위를 검증 사실처럼 옮기지 않는다. | 후순위 |
| 영업시간: 영업 중·24시간·요일/시간 | `24시간운영`·`야간운영`은 근거 개념과 자연어 조건이 있다. `현재영업중` 요청도 조건으로 파악하지만, 화면과 코드만으로 실시간 최신 영업시간 데이터가 확보됐다고 볼 수 없다. | 주간 시간표, 임시휴무, 마지막 확인 시각을 구조화한다. `24시간 표기`와 `지금 영업 중`을 분리한다. | 높음 |
| 속성: 배달·포장·예약 | `예약가능`·`포장가능`은 공식 필드 추출 대상, `테이크아웃전문`은 수집 대상이다. 배달은 현재 선택형 필터에 없다. | 가능/불가와 방식(방문 예약, 포장만, 배달 가능)을 분리하고 변경 시점을 기록한다. | 중간 |
| 네이버 예약·주문·결제·혜택 | 네이버 플랫폼 기능이며 우리 장소 근거의 범용 속성과 다르다. | 필요하면 외부 연결 가능 여부로 별도 관리한다. `예약 가능`과 `네이버 예약 가능`을 합치지 않는다. | 낮음 |
| 음식 종류: 한식·양식·아시아·일식·중식·분식·카페·뷔페 | 현재 선택형 장소 종류는 `식당`·`카페` 등 넓은 업종이다. 세부 음식 종류는 별도의 확정된 선택형 분류가 아니다. | 식당 하위 업종·메뉴 분류를 장소 종류로 관리한다. `특별한 메뉴` 같은 경험 태그와 분리한다. | 중간 |

## 3. 수집과 화면 구성의 우선순위

1. **보유량부터 측정:** 카페·식당을 우선으로 지역 × 업종 × 태그별 `전체 장소 / 현재 유효한 승인 긍정 근거가 있는 장소 / 미확인 후보 / 부정·충돌 / 만료`를 나눈다. 기존 보고 명령은 일부 핵심 태그만 다루므로 네이버 대조 항목 전체의 운영 보유량으로 오인하지 않는다.
2. **방문 실패를 막는 사실:** 영업시간, 예약, 접근성, 주차, 반려동물 동반 조건, 유아 의자, 포장 여부를 우선 보강한다. 가능/불가/미확인을 구분하고 시간·지점·조건을 함께 보관한다.
3. **우리 추천의 경험 근거:** 조용함, 대화, 혼자 이용, 작업·장기 체류, 좌석 형태를 카페·식당에서 보강한다. 검색어에만 맞는 장소를 확인된 추천으로 승격하지 않는다.
4. **화면 재구성:** `장소 종류 → 영업·이용 → 동행·접근성 → 공간·시설 → 분위기·목적`으로 묶는다. 각 선택은 `반드시 필요`와 `있으면 좋음`을 구분하고, 결과에는 확인/미확인/상충을 드러낸다. 현재 5개를 전체 서비스 기준처럼 노출하지 않는다.
5. **검색 연결 점검:** 새 항목마다 `정의 → 수집 → 검토 → 검색 계획 해석 → 후보 검색 → 조건 판정 → 결과 문구`의 모든 단계를 확인한다. 항목 추가만으로 필터가 작동한다고 간주하지 않는다.
