# 여기일지도 오류 수정 이력

마지막 갱신: 2026-09-09

이 문서는 대화에서 직접 재현했거나 코드·서버·실기기로 확인한 오류만 기록합니다. 자동 테스트 통과만으로 사용자 화면 문제가 해결됐다고 판단하지 않습니다.

## 검색과 지도

### 2026-09-09 전체 동작 감사 후 로컬 보정 (미배포)

- 일반 검색: DB 조회 생략 정책을 제거하고 이름/주소 조건을 먼저 제한해 DB 후보를 병합합니다. 상호에 들어간 업종 문자열 때문에 엉뚱한 업종으로 확장하지 않습니다. 공백 차이와 먼 지역의 DB 고유명사 검색을 함께 유지합니다.
- 지도 재검색: 모든 공급자 후보의 실제 좌표로 거리를 계산하고 최종 반경을 적용합니다. 가까운 후보가 없으면 지도 중심의 시/도 힌트로 Naver Local 후보를 보강합니다. 이 경로는 블로그/웹/AI 요약을 호출하지 않습니다.
- 좌표/지도: Naver Local WGS84 좌표만 지도에 전달하며 조건 검증 여부는 승격하지 않습니다. 상호 검색은 첫 선택 결과 위치로 이동하고 다른 후보 핀도 유지합니다. 일반/상황 지도의 현재 위치 버튼은 GPS 요청으로 연결하며 검색 중심을 GPS로 오표시하지 않습니다. 공유 지도 HTML도 함께 변경되어 향후 배포 시 앱과 함께 반영해야 합니다.
- 게시글: 좋아요/댓글/댓글 반응을 트랜잭션 안에서 정리하고 알림 참조를 해제합니다. 신고 기록은 삭제하지 않으며 대상 보존이 필요한 경우 이유를 안내합니다. 앱에 삭제 실패 메시지와 중복 실행 방어를 연결했습니다.
- 제보 초안: 외부 장소 이름/주소/초기 좌표별로 키를 분리하고 장소/계정 전환 시 폼을 새로 만듭니다. 기존 일반 새 장소 초안 키는 보존합니다.
- 보관함/MY: 저장 장소명에서 상세와 지도 링크를 다시 열 수 있습니다. 문의 답변 알림은 내 문의로 연결합니다(개별 문의 자동 펼침은 아님). 관리자 문의 상태와 근거 출처/판정 코드를 한글화했습니다.
- 로컬 확인: Django 전체836개 중815통과/21skip, Spring 전체110통과(실제 XML 합계), 지도 브리지·초안 키 회귀 스크립트 통과. 모바일 TypeScript/lint 및 웹 빌드 확인. 웹 빌드에는 기존 큰 청크 경고가 남습니다.
- 범위: 서버/DB 배포, EAS 업로드, APK 설치 없음. 새 코드+운영 PostgreSQL+실제 공급자+휴대폰 E2E는 아직 미검증입니다. 프로필 실제 업로드·재로그인·중단된 사진 제보 복구 등 이전 미검증 항목은 이 수정으로 통과 처리하지 않습니다.

### 역 이름 검색 누락 및 엉뚱한 동명 장소 노출

- 증상: 부산 좌표에서 `부산역`은 0건, `서울역`은 창원의 `서울역떡집`만 노출됐습니다.
- 원인: 좌표가 있으면 Kakao 거리순 첫 15개만 후보로 수집해 정확한 역이 후보군에 들어오지 못했습니다.
- 수정: 거리순 후보와 관련도순 후보를 함께 수집하고 정확한 장소명·지역 일치도를 우선하도록 변경했습니다.
- 확인: 운영 API와 실기기에서 `부산역` 검색 시 정확한 부산역이 첫 결과로 노출됐습니다.

### 지도 재검색에서 브랜드가 사라짐

- 증상: `스타벅스 카페` 검색 후 지도 중심 재검색을 하면 일반 카페가 표시됐습니다.
- 원인: 지도 모드가 카테고리 질의만 사용하면서 브랜드 키워드를 잃었습니다.
- 수정: 지도 재검색에서도 명시한 브랜드와 카테고리 의도를 함께 유지했습니다.
- 확인: 운영 API와 실기기에서 스타벅스 지점이 유지되는 것을 확인했습니다.

### 복합 지역명과 대화 지역 문맥 소실

- 증상: `부산 전포 카페`가 전포를 찾지 못했고, `부산 서면 분위기 좋은 카페`는 부산 전체로 축약됐습니다. AI가 실패한 뒤 후속 검색에서는 이전 지역과 조건이 사라졌습니다.
- 원인: 넓은 행정구역을 먼저 확정하고 세부 지역을 덮어썼으며, 실패 턴에서 마지막 유효 검색 프레임을 보존하지 않았습니다.
- 수정: 주소·지역 해석에서 더 구체적인 지역을 우선하고, AI 실패와 후속 조건 추가에서도 마지막 유효 프레임과 결과를 유지했습니다.
- 확인: 전포·서면 기준 검색과 후속 조건 흐름을 API 및 실기기에서 확인했습니다.

### 검증되지 않은 필수 조건 결과 자동 채움

- 증상: `주차 가능한 곳만`, `조용하고 무료인 곳만` 요청에 근거 없는 후보가 별도 동의 없이 채워졌습니다.
- 원인: 필수 조건 근거가 부족해도 best-available 후보를 자동 반환했습니다.
- 수정: 검증 후보가 없으면 부족함을 설명하고, 사용자가 완화에 동의한 뒤에만 미검증 대안을 제공합니다.
- 남은 한계: 검증 근거 보유율 자체는 아직 배포 게이트를 통과하지 못했습니다. 수집량과 승인 근거가 더 필요합니다.

### 비교 요청에 실질 비교가 없음

- 증상: `첫 번째랑 두 번째 비교해줘`에 결과 두 개만 다시 표시되고 조건·근거·링크 비교가 없었습니다.
- 수정: 직전 운영 결과의 조건, 근거와 상세 URL을 보존해 항목별 비교 문장을 생성하도록 변경했습니다.

### 공급자 지점명 표기 차이로 실제 장소가 0건

- 증상: 운영 앱에서 `그라츠커피랩 경성대점`은 0건이지만 `그라츠커피랩`은 Kakao 후보 19건을 반환했습니다.
- 원인: 완전한 지점명 질의가 Kakao 후보를 하나도 만들지 못하면 더 긴 공급자 지점명 표기를 찾을 수 없었고, 후처리도 입력의 `경성대점`을 그대로 요구했습니다.
- 수정: 완전 질의가 0건일 때만 `점` 접미사를 제한적으로 완화해 한 번 더 수집하고, `경성대부경대점`처럼 더 긴 지점명도 원래 입력과 일치하도록 판정합니다. 일반 검색과 상황 검색의 Kakao 수집기에 동일하게 적용했습니다.
- 확인 경계: 회귀 테스트를 추가하고 Python 문법 검사를 통과했습니다. 로컬 PostgreSQL이 실행 중이지 않아 Django 테스트와 운영 반영 후 실제 Kakao 재검증은 아직 남았습니다.

### Kakao에도 없는 실제 상호가 계속 0건

- 증상: 실제 영업 중인 `그라츠커피랩 경성대점`은 지점명 완화와 지점 주변 재검색을 해도 Kakao Local 후보가 0건이었습니다.
- 원인: 일반 검색의 외부 후보원이 Kakao 하나뿐이라 공급자 데이터에 없는 장소는 저장 DB에 들어오기 전까지 복구할 경로가 없었습니다.
- 수정: 저장 DB와 Kakao가 모두 0건인 고유 장소명에만 Naver 로컬·웹 검색을 최후 후보로 사용합니다. 이 결과는 `네이버 검색 후보`로 표시하고, 좌표가 검증되지 않은 동안 지도 핀으로 만들지 않습니다. 동일 질의는 5분 동안 캐시해 외부 검색 지연과 요청량을 줄였습니다. 상황 검색의 지점명 재검색도 지점 위치를 먼저 해석하도록 맞췄습니다.
- 확인: 격리 회귀 테스트 18개가 통과했습니다. 운영 API에서 해당 상호가 1건 반환됐고 후보 집계는 DB 0/Kakao 0/Naver 1이었습니다. 연속 요청 시간은 822ms, 401ms였습니다.

## 모바일 화면과 성능

### 장소 상세 화면이 열리지 않음

- 증상: 장소명과 별도 상세보기 버튼을 눌러도 웹 상세가 열리지 않았습니다.
- 원인: 부모 Modal을 먼저 숨긴 뒤 그 안의 자식 Modal을 열어 Android에서 자식이 렌더링되지 않았습니다.
- 수정: 상세 표시 상태의 소유권과 Modal 가시성 연결을 바로잡고, 지도 아래 장소명도 동일한 상세 흐름으로 연결했습니다.
- 확인: 에뮬레이터와 실기기에서 기본 상세 및 Kakao 상세 WebView가 열렸습니다.

### 입력란 안내 문구가 보이지 않음

- 증상: 로그인·검색·제보 등 입력란이 모두 빈칸처럼 보여 무엇을 입력해야 하는지 알기 어려웠습니다.
- 원인: 일부 입력에 placeholder가 없거나 배경과 대비가 부족했습니다.
- 수정: 모바일 TextInput에 용도별 안내 문구와 명시적인 고대비 placeholder 색상을 적용했습니다.
- 확인: 로그인과 장소 제보를 포함한 실기기 화면에서 확인했습니다.

### 프로필 사진 변경이 시작되지 않음

- 증상: 프로필 사진 변경을 눌러도 변경되지 않았습니다.
- 확인: 같은 시간대 운영 게이트웨이에 `/accounts/me/profile-image` 요청이 한 건도 없어 서버 저장 이전의 모바일 사진 선택 단계에서 중단된 것으로 확인했습니다.
- 수정: 사진 접근 권한을 명시적으로 확인하고, 선택 파일·지원 형식을 검증하며, 처리 중 상태와 권한/형식/API 오류 원문을 화면에 표시하도록 변경했습니다.
- 확인 경계: 모바일 TypeScript와 lint는 통과했습니다. 새 APK에서 권한 허용·거부 및 실제 업로드 재검증이 필요합니다.

### 로딩과 빈 상태를 구분하기 어려움

- 증상: 특히 관리자 화면에서 데이터가 없는지 로딩 중인지 알 수 없었고, 전체 화면이 느리게 느껴졌습니다.
- 원인: 빈 배열을 초기 상태로 사용했고 오류·재시도 표시가 화면마다 달랐습니다. 인증 저장소 반복 접근, 불필요한 GPS 대기, 큰 검색 응답, 지도 WebView 재마운트도 지연을 더했습니다.
- 수정: 공통 로딩·빈 상태·오류·재시도 UI, 인증 캐시, 제한 시간 위치 조회, 경량 목록 응답, 지도 재사용을 적용했습니다. 공공 카테고리는 충분한 DB 결과가 있으면 불필요한 외부 검색을 건너뜁니다.
- 확인: 관련 타입·테스트와 운영 API 스모크를 통과했지만, 통신 환경과 첫 요청의 외부 제공자 지연은 계속 관찰해야 합니다.

### 위치 없는 결과가 0m로 표시됨

- 증상: 좌표나 거리 정보가 없는 장소가 `0m`로 표시됐습니다.
- 수정: 실제 거리 값이 없으면 `거리 정보 없음`으로 표시하도록 변경했습니다.

### 오프라인 내부 오류 노출

- 증상: 네트워크가 끊기면 Java `UnknownHostException`과 내부 호스트명이 사용자에게 노출됐습니다.
- 수정: 내부 예외와 호스트를 제거한 한국어 네트워크 안내 및 재시도 흐름으로 통일했습니다.
- 확인: 에뮬레이터에서 오프라인과 복구 후 재시도를 확인했습니다.

### 장소 보관함이 404로 열리지 않음

- 증상: 모바일 `장소 보관함` 진입 시 `요청에 실패했습니다. (404)`가 표시됐습니다.
- 원인: 저장 장소 그룹 API는 Spring에 있지만 모바일 API 분기 목록에 `/recommendations/saved-place-groups`가 빠져 요청이 Django로 전달됐습니다.
- 수정: 저장 장소 그룹의 조회·생성·수정·삭제 요청을 Spring API로 일관되게 분기합니다.
- 확인: Spring 컨트롤러 경로와 모바일 요청 경로를 대조하고 모바일 TypeScript와 lint를 통과했습니다. 로컬 Release APK를 Samsung SM-F741N에 덮어쓰기 설치한 뒤 그룹 생성 UI와 정상 빈 상태가 표시되고 404가 사라진 것을 확인했습니다.

### 좌표 없는 웹 후보가 지도에 `0`번 핀으로 나타남

- 증상: 좌표가 없는 네이버 검색 후보를 선택하면 지도에 `0` 라벨의 잘못된 핀이 나타났습니다.
- 원인: 전체 결과 모드는 좌표를 검사했지만 선택 결과 모드는 검사를 우회했고, `Number(null)`이 `0`으로 변환됐습니다.
- 수정: 선택·전체 모드가 동일한 좌표 유효성 검사를 사용합니다. 좌표 없는 후보는 목록과 상세에는 남지만 지도 마커와 길찾기에는 사용하지 않습니다.
- 확인: 모바일 TypeScript와 lint를 통과했습니다. 실기기에서 좌표 없는 `그라츠커피랩 경성대점` 결과를 다시 열어 지도에 `0` 핀이 생성되지 않고 목록·상세는 유지되는 것을 확인했습니다.

### 네이버 후보 상세에 카카오 제공 문구가 노출됨

- 증상: 정보 출처는 `네이버 검색 후보`인데 안내와 실패 버튼은 카카오 정보라고 표시됐습니다.
- 수정: Kakao 출처는 카카오 문구를 유지하고, 그 외 외부 후보는 `원문 상세정보`와 `원문에서 열기`로 표시합니다. 좌표와 Kakao URL이 모두 없으면 Kakao 길찾기 버튼도 숨깁니다.
- 확인: 모바일 TypeScript와 lint를 통과했습니다. 실기기 상세 시트에 `원문 상세정보`가 표시되고 카카오 길찾기 버튼은 숨겨졌으며, 원문 WebView가 실제 외부 페이지를 연 것을 확인했습니다.

### 제보 목록에 내부 코드가 그대로 노출됨

- 증상: 사용자·관리자 제보 목록에 `pending`, `rejected`, `new_place` 같은 내부 코드가 표시됐습니다.
- 수정: 상태는 `검토 대기·승인·반려`, 유형은 `새 장소·태그 추가·정보 수정`으로 공통 변환합니다. 서버가 번역 라벨을 주면 그 값을 우선합니다.
- 확인: 모바일 TypeScript와 lint를 통과했습니다. 실기기 사용자·관리자 목록에서 `검토 대기·반려·새 장소`가 표시되는 것을 확인했습니다.

## 장소 제보

### 관리자 승인·반려 버튼을 찾기 어려움

- 증상: 관리자 장소 제보 목록은 열리지만 승인 절차와 버튼을 찾기 어려웠습니다.
- 원인: 목록 버튼이 `사진·본문 확인 및 검토`로만 표시되고, 상세의 승인·반려 영역은 큰 첨부 사진 아래에 배치됐습니다. 운영 접근 기록에서도 목록만 열고 상세는 열지 않은 것이 확인됐습니다.
- 수정: 검토 대기 카드의 기본 동작을 `상세 확인 후 승인·반려`로 명확히 표시하고, 상세에서는 사진을 가로 미리보기로 압축한 직후 관리자 검토 영역과 승인·반려 버튼을 노출합니다.
- 확인 경계: 모바일 정적 검사는 통과했으며 새 APK에서 실제 관리자 동작 검증이 필요합니다.

### 제보가 접수됐는지 알 수 없고 재시도 시 중복 위험

- 증상: 사용자가 제보를 시도했지만 서버에는 요청 기록과 접수 행이 없었고, 성공 영수증이나 복구 수단도 없었습니다.
- 수정: 클라이언트 요청 UUID를 저장하고 사용자별 멱등 접수를 적용했습니다. 응답을 잃어 재전송해도 같은 영수증을 반환합니다. 작성 필드·태그·좌표·사진은 접수 성공 전까지 앱 저장소에 유지됩니다.
- 확인: 같은 UUID 요청이 최초 201, 재요청 200과 동일 영수증을 반환하고 중복 행을 만들지 않는 것을 트랜잭션 롤백 검증으로 확인했습니다.

### 휴대폰 GPS 소수점 자릿수로 제보 실패

- 증상: 휴대폰이 보낸 7자리 좌표가 서버의 소수점 6자리 스키마 검증에서 거절됐습니다.
- 수정: 모바일 제출과 서버 검증 전에 반올림해 6자리로 정규화했습니다.
- 확인: 실기기 접수·관리자 검토·사용자 상태 확인까지 완료했습니다.

### 지도 핀과 현재 위치 버튼

- 증상: 지도에서 제보 위치를 고를 수 없었고, 빈 좌표가 숫자 `0`으로 변환되어 `(0,0)`에 잘못된 초기 핀이 나타났습니다. 오른쪽 아래 원형 버튼도 현재 위치 이동 의미와 다르게 동작했습니다.
- 수정: 빈 좌표를 핀으로 만들지 않고, 지도 탭으로 제보 좌표를 선택하도록 연결했습니다. 원형 버튼은 호스트에 현재 위치를 요청하고 지도·선택 핀·현재 위치점을 함께 이동시킵니다.
- 확인: Samsung SM-F741N에서 지도 탭 좌표 변경, 현재 위치 `35.096458, 128.853954` 복귀, 강제 종료 후 초안 복구를 확인했습니다.

## 빌드와 설치

### EAS APK 서명 불일치

- 증상: 첫 보정 APK가 기존 설치 앱과 다른 인증서로 서명되어 업데이트 설치할 수 없었습니다.
- 원인: EAS 업로드에 로컬 `android/`가 포함되어 체크인된 디버그 서명 설정이 적용됐습니다.
- 수정: `.easignore`, 절대 `EAS_PROJECT_ROOT`, 원격 자격 증명 고정을 적용했습니다. 설치 전 패키지명과 인증서 SHA-256을 반드시 검사합니다.
- 확인: 최종 Preview APK의 패키지 `com.binkim00.lifeinframap.test`와 기존 서명이 일치한 뒤에만 `adb install -r`로 설치했습니다.

## 아직 구체 정보가 필요한 항목

- 사용자가 말한 `핏플 오류`가 여기일지도 내부 기능의 별칭인지 별도 프로젝트 앱 오류인지 대화만으로 확정할 수 없습니다. 다른 프로젝트 앱은 임의로 조사하거나 수정하지 않았습니다. 정확한 화면, 입력, 오류 문구를 받으면 이 문서에 별도 항목으로 추가합니다.
