# 데이터 수집 및 정제 작업 정리

## 작업 목적

오늘 작업은 상황 기반 생활 장소 추천 지도 서비스에서 사용할 외부 장소 데이터를 확보하고, 추천 API와 Django DB에서 공통적으로 활용할 수 있는 형태로 정제하는 것을 목표로 진행했습니다.

기존 프로젝트에는 흡연구역 데이터와 일부 테스트 데이터가 있었으나, 서비스의 추천 범위를 넓히기 위해 주차장, 관광 데이터, 해수욕장, 도시공원, 공공와이파이, 공중화장실 데이터를 수집 및 정제했습니다.

## 1. 추가 데이터 수집

### 1.1 주차장 데이터 수집

공공데이터포털의 전국주차장정보표준데이터를 CSV 형태로 수집했습니다.

저장 위치는 다음과 같습니다.

```text
ExData/CSVData/parking/전국주차장정보표준데이터.csv
```

주요 활용 컬럼은 다음과 같습니다.

```text
주차장명
주차장구분
주차장유형
소재지도로명주소
소재지지번주소
위도
경도
요금정보
운영요일
평일운영시작시각
평일운영종료시각
토요일운영시작시각
토요일운영종료시각
공휴일운영시작시각
공휴일운영종료시각
장애인전용주차구역보유여부
데이터기준일자
```

이 데이터는 `무료주차`, `공영주차장`, `노외주차장`, `24시간운영후보`, `장애인주차구역있음` 등의 태그 생성에 활용할 수 있습니다.

## 2. 데이터 정제 방향 결정

수집한 원본 데이터는 CSV와 JSON 형식이 섞여 있고, 출처마다 컬럼명이 다르기 때문에 서비스에서 바로 사용하기 어렵습니다.

따라서 모든 데이터를 공통 Place 구조로 변환하는 정제 방식을 적용했습니다.

공통 정제 구조는 다음과 같습니다.

```json
{
  "name": "장소명",
  "category": "장소 카테고리",
  "address": "주소",
  "lat": 35.1234,
  "lng": 129.1234,
  "source": "데이터 출처 코드",
  "external_id": "출처 기반 고유 ID",
  "source_name": "데이터 출처명",
  "source_updated_at": "데이터 기준일",
  "detail_location": "상세 위치",
  "data_quality_status": "usable",
  "data_quality_score": 80,
  "default_tags": [],
  "candidate_tags": [],
  "warning_tags": [],
  "raw": {}
}
```

각 필드의 역할은 다음과 같습니다.

| 필드                    | 역할               |
| --------------------- | ---------------- |
| `name`                | 장소명              |
| `category`            | 서비스 내부 장소 분류     |
| `address`             | 주소               |
| `lat`                 | 위도               |
| `lng`                 | 경도               |
| `source`              | 데이터 출처 코드        |
| `external_id`         | 원본 데이터 기준 고유 식별자 |
| `source_name`         | 사람이 읽을 수 있는 출처명  |
| `source_updated_at`   | 데이터 기준일          |
| `detail_location`     | 상세 위치 설명         |
| `data_quality_status` | 사용 가능 상태         |
| `data_quality_score`  | 데이터 품질 점수        |
| `default_tags`        | 장소의 기본 정체성 태그    |
| `candidate_tags`      | 추천에 활용할 후보 태그    |
| `warning_tags`        | 주의 또는 확인 필요 태그   |
| `raw`                 | 원본 데이터 전체 보관     |

## 3. 태그 분류 기준

정제 과정에서 원본 데이터를 기반으로 자동 태그를 생성했습니다.

### 3.1 default_tags

장소의 기본 정체성을 나타내는 태그입니다.

예시:

```text
주차장
공영주차장
공원
해수욕장
공중화장실
공공와이파이
관광명소
문화시설
```

### 3.2 candidate_tags

추천 조건으로 활용할 수 있는 세부 특성 태그입니다.

예시:

```text
무료주차
24시간운영후보
장애인주차구역있음
산책후보
휴식후보
화장실있음
주차장있음
운동시설있음
어린이놀이터있음
관광지와이파이
교통시설와이파이
비상벨있음
기저귀교환대있음
```

### 3.3 warning_tags

정보 부족 또는 현장 확인이 필요한 경우에 붙이는 주의 태그입니다.

예시:

```text
운영시간확인필요
요금정보확인필요
주소확인필요
기준일확인필요
연락처확인필요
개방시간확인필요
시설정보확인필요
```

## 5. 정제 결과 파일

정제된 결과 파일은 다음 위치에 저장했습니다.

```text
ExData/Cleaned/
```

생성된 주요 정제 파일은 다음과 같습니다.

```text
beach_places.json
tourism_places.json
parking_places.json
citypark_places.json
freewifi_places.json
toilet_places.json
```

정제 과정에서 좌표가 없거나 이름이 없는 데이터는 서비스 지도 표시가 어렵기 때문에 별도로 분리했습니다.

제외 데이터는 다음 위치에 저장했습니다.

```text
ExData/Cleaned/skipped/
```

생성된 제외 데이터 파일은 다음과 같습니다.

```text
beach_skipped.json
tourism_skipped.json
parking_skipped.json
citypark_skipped.json
freewifi_skipped.json
toilet_skipped.json
```

## 6. 데이터 정제 기준

정제 시 다음 기준을 적용했습니다.

### 6.1 지도 표시 가능 여부

지도 서비스 특성상 위도와 경도가 없는 데이터는 바로 사용할 수 없으므로 `skipped` 데이터로 분리했습니다.

```text
name 없음 → skipped
lat 없음 → skipped
lng 없음 → skipped
```

### 6.2 원본 데이터 보존

원본 CSV/JSON의 모든 값은 `raw` 필드에 보존했습니다.

이를 통해 나중에 태그 생성 규칙을 수정하거나, 특정 태그가 왜 붙었는지 확인할 수 있습니다.

### 6.3 추천용 태그 자동 생성

원본 컬럼에 포함된 정보를 기반으로 추천 태그를 자동 생성했습니다.

예를 들어 주차장 데이터의 경우:

```text
요금정보 = 무료
→ 무료주차

주차장구분 = 공영
→ 공영주차장

평일운영시작시각 = 00:00, 평일운영종료시각 = 23:59
→ 24시간운영후보

장애인전용주차구역보유여부 = Y
→ 장애인주차구역있음
```

도시공원 데이터의 경우:

```text
편익시설에 화장실 포함
→ 화장실있음

편익시설에 주차장 포함
→ 주차장있음

운동시설 값 존재
→ 운동시설있음

공원면적이 일정 기준 이상
→ 대형공원후보 또는 넓은공원후보
```

## 8. 아직 남은 작업

정제된 데이터는 아직 Django DB에 들어간 상태가 아닙니다.

다음 단계는 정제 결과와 팀원이 만든 카페 태그 데이터를 함께 Django DB에 import하는 작업입니다.

남은 작업은 다음과 같습니다.

```text
1. 정제된 JSON 파일을 Django DB에 import
2. Place 모델에 장소 저장
3. Tag 모델에 태그 저장
4. PlaceTag 모델에 장소-태그 관계 저장
5. 사용자의 자연어 검색을 카테고리와 태그 조건으로 변환
6. DB에서 태그, 카테고리, 거리, 신뢰도 기준으로 장소 추천
7. 추천 결과를 지도와 카드 UI에 표시
```
