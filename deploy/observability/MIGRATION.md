## 전환 조건

1. 기초 스냅샷 `snap-02513cdde15ec27f1`의 `completed` 상태를 확인한다. 이후 구서버 쓰기가 재개됐으므로 이것만 복원해 운영 전환하면 안 된다.
2. 후보의 Grafana/Loki 합성 검사 기록과 설치 파일을 확보한다. 합성 로그·후보의 초기 관리자 비밀번호를 운영 자료로 복제하지 않는다.
3. 구서버의 공개 진입점, scheduler/worker, 앱 API 쓰기와 프로젝트 timer/service 작업을 중지한다. 강제 종료 대신 정상 중지·DB 트랜잭션 종료를 확인한다.
4. 운영 DB가 계속 켜진 상태에서 `db_fingerprint.py`로 모든 public 테이블의 정확한 건수를 기록한다. 이는 전체 행의 값·해시 비교를 대체하지 않는다. 동일 데이터의 보존은 최종 정합 디스크 복제로 확보한다.
5. DB를 정상 종료하고 구서버를 중지한다. 쓰기가 없는 최종 스냅샷을 만들고 완료를 확인한다. 이 상태의 구서버는 되돌리기용으로 유지한다.
6. 서울 2b에 최종 스냅샷의 40GiB gp3 암호화 볼륨을 생성해 후보에 보조 볼륨으로 연결한다. NVMe serial로 정확한 새 볼륨을 식별하고 명시적 파티션을 마운트한다. 원본 구서버 볼륨에는 연결/포맷/수정하지 않는다.
7. `prepare_clone.py`를 오프라인 마운트에만 적용한다. 사설 IP 변경, 9개 컨테이너 자동 시작 보류, 프로젝트 timer 활성 링크 보류와 복구 recipe를 기록한다. DB·미디어·백업은 수정하지 않는다.
8. 검증된 모니터링 파일과 이미지 digest 기록을 복제 루트에 복사한다. 후보를 중지하고 UserData 재실행을 비워 기존 앱의 재설치/업그레이드를 막는다. bootstrap 루트와 복제 루트를 명확히 구분해 `/dev/sda1`을 교체한다. 동일 filesystem UUID 볼륨 두 개를 동시에 부팅 루트로 연결하지 않는다.
9. 새 서버 부팅 후 구서버가 중지됐는지 확인한다. 복제된 Tailscale 장치 신원은 두 서버에서 동시에 활성화하지 않는다. 필요하면 신규 Tailscale 장치 등록으로 분리하되 연결 주소 변경을 먼저 반영한다.
10. DB만 먼저 시작하고 `db_fingerprint.py --expect`의 건수 일치를 확인한다. 이후 storage·Spring·Django·gateway·Caddy를 시작하고 내부 및 공개 Host 이름을 지정한 HTTPS 건강 검사를 수행한다.
11. 실제 운영 컨테이너 로그 경로로 `prepare.py`를 실행한다. Grafana는 확인된 Tailscale 주소에만 공개하고 Loki는 호스트 포트를 열지 않는다. datasource·대시보드·실제 정제 로그·민감 필드 제거·디스크·OOM을 확인한다.
12. 고정 IP를 새 서버에 연결하고 도메인 HTTPS/API/저장소 상태를 직접 확인한다. 그 뒤 scheduler/worker, restart policy, timers를 원래 상태로 복구한다. 기존 CloudWatch의 인스턴스 대상과 heartbeat를 새 서버로 연결하고 백업 상태를 확인한다.
13. 검증 결과를 state에 기록한다. 구서버는 우선 중지 보존한다. 실행 중인 새 DB에 쓰기가 발생한 뒤 구서버로 원복할 경우에는 신규 데이터 정합성을 별도로 확보해야 한다.
